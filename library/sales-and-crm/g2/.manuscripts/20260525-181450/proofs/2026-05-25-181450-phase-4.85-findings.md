# Phase 4.85 Agentic Output Review — Findings

Status: WARN (3 findings, all severity: warning — Wave B non-blocking)

## Findings

### 1. CSV empty-result emits literal `null`
**Check:** format-bugs
**Severity:** warning
**Description:** `buyer-intent list --csv` prints the four-character literal `null` to stdout instead of an empty CSV body or a header-only row; downstream CSV parsers will choke or treat `null` as a one-cell data row.
**Suggestion:** In CSV writers, when the result set is empty, emit either the header row alone or nothing; never serialize a Go `nil` slice as the literal token `null` for `--csv` mode.

### 2. `watch products` unsynced state confuses scripted consumers
**Check:** format-bugs
**Severity:** warning
**Description:** `watch products --product datadog,new-relic,dynatrace --json` returns objects with `product_name: ""` and all-zero rating/review counts whenever the local store is unsynced, while still exiting 0; a scripted consumer would read this as "no activity for Datadog" rather than "no data synced yet."
**Suggestion:** When the local store has no rows for a requested product, either omit the object and surface it under an `unsynced_products` list, or include an `unsynced: true` flag on each placeholder object so JSON consumers can distinguish missing-data from real-zero.

### 3. Live-check sample probe accepts `null` state as PASS
**Check:** ranking-plausibility
**Severity:** warning
**Description:** Five of seven passing sampled commands (`analytics` x2, `buyer-intent list`, `reviews list`, `watch market-signals`) return bare `null` with no synced data, so the rule-based live-check accepted them but the sample provides zero evidence that ranking, filtering, or aggregation logic is actually correct on real data.
**Suggestion:** Have shipcheck's live-check seed the local store with a tiny fixture (`sync --resources products,reviews --limit 5`) before sampling, or extend the example invocations to include a `--demo-data` flag so the reviewer can judge real ordering/filtering output rather than null-state placeholders.

## Disposition

Per Wave B rollout policy, these are non-blocking warnings. Polish phase (5.5) may address #1 and #2. Finding #3 is a Printing Press machine improvement candidate (retro).
