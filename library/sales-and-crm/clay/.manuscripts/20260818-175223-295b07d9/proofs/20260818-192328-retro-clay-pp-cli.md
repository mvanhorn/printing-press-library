## Findings

### F1. Capture-time redaction misses credentials in header VALUES (Bug)
- **What happened:** A live third-party credential (`Authorization: Basic <base64 user:pass>`)
  configured by the user inside an HTTP-API column passed through the browser-sniff redaction
  untouched, landing in the on-disk capture artifact and in agent context. Detected only by
  manual inspection of an unrelated extraction.
- **Scorer correct?** N/A — not a score-penalty finding.
- **Root cause:** `skills/printing-press/references/browser-sniff-capture.md` redaction guidance
  targets `"apiKey"`-shaped JSON *fields*. Credentials living as header *values* inside a
  captured request body (a `formulaMap`, a headers object, any nested map) are not matched.
- **Cross-API check:** Recurs on any browser-sniff run where the user has configured an
  outbound credential in the product being captured. Independent of the API's own auth.
- **Frequency:** subclass — every browser-sniff capture of a product that lets users store
  third-party credentials (integration platforms, workflow builders, iPaaS, scrapers).
- **Fallback if the Printing Press doesn't fix it:** The agent must notice by eye. In this run
  the agent did notice, but only incidentally; a run that did not inspect that particular
  request would have archived the credential.
- **Worth a Printing Press fix?** Yes. A redaction routine that ships an incomplete pattern set
  is a machine defect, not agent error — the playbook is what the agent is told to trust.
- **Inherent or fixable:** Fixable. Widen the pattern set.
- **Durable fix:** In the capture reference, redact (a) any `Authorization` value regardless of
  scheme, (b) `Bearer`/`Basic`/`Token` blobs anywhere, (c) `x-api-key`-style header names, and
  (d) base64 blobs that decode to `user:pass`. **Also add an explicit scope rule: scrub request
  and response BODIES only, never URL/host fields.** A corrective pass in this run over-matched
  with a blind base64 sweep and corrupted URL path segments in the artifact, which is its own
  failure mode worth documenting alongside the fix.
- **Test:** positive — a capture containing `Authorization: Basic dXNlcjpwYXNz` in a nested body
  map redacts. negative — a URL containing a long base64-ish path segment is left intact.
- **Evidence:** Session moment where an HTTP-API column's `inputsBinding.headers.formulaMap`
  carried a live vendor credential into `discovery/*-capture.json`.
- **Related prior retros:** None on this machine (first retro here). Related open issues:
  #3768 (`extends` — credential handling hardening in skills, different mechanism: chat paste +
  exact-value scans), #3780 (`extends` — PII in archived captures, adjacent surface).

### F2. Capture playbook arms interceptors after first paint, hiding initial data loads (Skill instruction gap)
- **What happened:** Following the documented flow, fetch/XHR interceptors were installed on an
  already-loaded SPA. Every initial data load had already fired, so the app's row-read path was
  never observed. This produced a false "row listing is unresolved" gap that was written into
  the absorb manifest and nearly shipped as a documented limitation.
- **Scorer correct?** N/A.
- **Root cause:** `browser-sniff-capture.md` Cardinal Rule 3 tells the agent to install
  interceptors and then navigate *by clicking*, explicitly to avoid the reload that would reset
  the JS context. That correctly preserves the interceptor but guarantees the first paint is
  never captured. Nothing in the reference says to arm before first paint.
- **Cross-API check:** Recurs on every client-rendered SPA capture, which is the majority of
  browser-sniff targets.
- **Frequency:** most browser-sniffed CLIs.
- **Fallback:** The agent must independently realise the initial load was missed. In this run it
  was caught only because a later user question forced a second look.
- **Worth a Printing Press fix?** Yes — the current instruction actively teaches the wrong order.
- **Inherent or fixable:** Fixable, and cheaply: CDP `Page.addScriptToEvaluateOnNewDocument`
  installs a recorder that runs before page scripts and survives reloads.
- **Durable fix:** Document the CDP pre-navigation install as the default for SPA capture, with
  the click-navigation rule demoted to the fallback for when CDP is unavailable.
- **Test:** positive — capture of an SPA table view records the initial list/detail fetches.
  negative — a static HTML target still captures without requiring CDP.
- **Evidence:** Row-listing flow (a view-scoped id list followed by a bulk cell fetch) was
  invisible across three capture attempts and only appeared after a pre-paint recorder was used.
- **Related prior retros:** None. No matching open issue found.

### F3. Capture playbook targets a removed browser-use CLI surface (Bug)
- **What happened:** The reference instructs the agent to run `browser-use open` and
  `browser-use eval`. Both were removed in browser-use CLI 3.0 and now print a migration error.
- **Scorer correct?** N/A.
- **Root cause:** `browser-sniff-capture.md` was written against browser-use <= 2.x. 3.0 replaced
  the preset subcommands with stdin-piped Python plus helpers (`new_tab`, `js`, `cdp`,
  `list_tabs`, `switch_tab`) and auto-attaches to the running browser over CDP.
- **Cross-API check:** Affects every run whose capture backend resolves to browser-use >= 3.0,
  regardless of API.
- **Frequency:** every browser-sniff run on a current install.
- **Fallback:** The agent must reverse-engineer the new interface mid-run from `--help` output.
- **Worth a Printing Press fix?** Yes — a documented command that errors out is a correctness
  defect in the skill, not polish.
- **Inherent or fixable:** Fixable; version-aware instructions.
- **Durable fix:** Update the reference to the 3.0 interface and note the auto-attach behavior
  (which also removes the separate session-transfer step the reference currently describes).
  Secondary note: the upstream `interaction-skills/network-requests.md` the browser-use skill
  points at is currently a one-line stub with no content, so it cannot be relied on.
- **Test:** positive — documented capture commands execute on browser-use 3.x. negative —
  guidance still degrades to manual HAR when no backend is present.
- **Evidence:** `browser-use open --help` returned "The browser-use CLI changed in 3.0, and
  'open' was removed."
- **Related prior retros:** None. No matching open issue found.

### F4. Cookie-auth CLIs discard the stored session when any env credential exists (Bug)
- **What happened:** For an API with a browser-session credential for one path prefix and an
  API-key credential for another, the generated CLI sent the api-key header on every request
  (including the cookie-only surface), seeded the cookie jar with the api-key value, and
  discarded the stored browser session entirely whenever an env credential was present. Net
  effect: exporting the documented env var broke every app-API command.
- **Scorer correct?** N/A — surfaced by live testing, not a score penalty.
- **Root cause:** In generated config, `CookieCredential()` prefers the env api-key over the
  stored session token, and `UsePersistedCookieJar()` returns false whenever `AuthSource` begins
  with `env:`. Together these mean "an env credential exists" is treated as "the browser session
  is stale," which is wrong when the two credentials authenticate different surfaces.
- **Cross-API check:** Recurs for any cookie/browser-session CLI that also reads an env
  credential — including single-surface CLIs where a user has an unrelated env var set.
- **Frequency:** subclass — cookie/composed-auth CLIs, which are a large share of
  browser-sniffed prints.
- **Fallback:** Hand-patching generated config and client files, which regen then reverts
  (see #4067).
- **Worth a Printing Press fix?** Yes, but as an extension of existing work rather than a new
  issue — #2512 already tracks the cookie/browser-session auth gap family and lists adjacent
  env-var miswiring for the same auth mode.
- **Inherent or fixable:** Fixable.
- **Durable fix:** Treat a stored browser session as authoritative for cookie-mode requests even
  when an env credential is present, and scope non-cookie credentials to the path prefix or
  base-URL they actually authenticate. The spec's `tier_routing` is the natural home but
  currently excludes cookie tiers by explicit documented carve-out.
- **Test:** positive — a cookie-auth CLI with an unrelated env credential set still authenticates
  its cookie surface. negative — a pure api-key CLI is unaffected.
- **Evidence:** Both surfaces returned 401 until the two precedence rules were patched; verified
  working simultaneously afterwards.
- **Related prior retros:** None on this machine. Open issues: #2512 (`extends` — same auth-mode
  family, different specific defects), #4067 (`aligned` — explains why the hand-patch does not
  survive regen).

## Anti-patterns
- **Redacting by field name rather than by value shape.** The capture redaction matched
  `"apiKey":`-style keys; the credential that leaked was a header value in a nested map.
  Value-shape matching (scheme prefixes, decodable base64 pairs) is the durable form.
- **Over-correcting a redaction miss.** The first corrective pass swept all long base64-ish
  tokens and corrupted URL path segments in the artifact, destroying evidence. Redaction scope
  must be bounded to bodies.
- **Trusting an interceptor installed after page load.** A recorder armed post-paint cannot
  observe the loads that already fired, and its silence reads as "the endpoint does not exist."
- **Filing before verifying.** Two candidates in this retro were disproven by reading the actual
  artifact and schema; a third and fourth were already filed upstream with better evidence.

## What the Printing Press Got Right
- **The Multi-Source Priority Gate worked.** Two sources were named, priority was confirmed and
  recorded, and the shipped CLI preserved it — primary 27 endpoints vs secondary 4, primary
  leading the README, and the paid credential correctly scoped to secondary commands only. No
  inversion.
- **`regen-merge` preserved every hand-authored novel file** across five regenerations
  (20+ preserved files), which is what made a 12-feature hand-built layer survivable at all.
- **The live-dogfood matrix caught real defects** that structural checks passed: an invalid enum
  value, a nonexistent flag in narrative docs, and a documented-but-unimplemented flag.
- **Phase 3's mechanical command-path gate** caught a manifest command path that the generator
  had legitimately collapsed, before it reached docs.
- **The acceptance marker's `source_fingerprint`** is present and correct, which appears to
  resolve the gap described in open #3949.
