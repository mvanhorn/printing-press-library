Generated from ScreenCloud's [official GraphQL sitemap](https://screencloud.github.io/signage-next-graphql-docs/sitemap.xml) on 2026-07-31. The documentation currently identifies itself as API v2.103.0.

This is a complete index of the root query and mutation reference pages and every published GraphQL type page. It is an atlas, not a claim that every operation is appropriate for the Playgrounds-focused CLI. Billing, identity, destructive administration, and other non-Playgrounds domains remain visible here so scope decisions are explicit.

ScreenCloud states that its GraphQL schema is continually evolving and does not have fully implemented schema versioning. Regenerate this file before generation or release when contract drift matters.

## Playgrounds-adjacent topology

The impact path does not stop at `AppInstance -> Space`. The published schema exposes:

- `AppInstance.sharedSpacesByAppInstanceId`, share associations, placement associations, casted screens, files, and its resolved app version.
- `Channel.appInstancesByChannelId`, `playlistsByChannelId`, and `screensByChannelId`.
- `Playlist.appInstancesByPlaylistId` and placement/share associations.
- `Screen.appInstancesByScreenId`, `channelsByScreenId`, `playlistsByScreenId`, and screen-content history.
- `ShareAssociation` edges between a source space, destination space, and shared app instance/channel/playlist/content object.

A trustworthy release-impact command must traverse direct assignment, nested playlist/channel placement, casting, and cross-space sharing, then deduplicate screens before reporting blast radius.

## Permission model

The live read-only schema exposes `currentToken`, `currentUser`, and `permissionsList`. Token and user permission lists are string arrays; `permissionsList` is a domain-to-action catalog. Playgrounds-relevant domains include `app`, `app_instance`, `channel`, `playlist`, `screen`, `space`, `token`, and `permission_sets`.

A capability diagnostic should compare the authenticated token's permissions with the operations required by each CLI command family. It must report unknown or missing permission strings without attempting a mutation, and it must never print the token value.
