## Contract (docs.oracle.com, REST API for Oracle Fusion Cloud HCM)
- `GET /hcmRestApi/resources/11.13.18.05/recruitingCEJobRequisitions` (clients often use /resources/latest/). Finder `findReqs` variables: correctedKeyword, executeSpellCheckFlag, facetsList, hotJobFlag, jobFamilyId, keyword, lastSelectedFacet, latitude, limit, location, locationId, longitude, offset, organizationId, postingEndDate, postingStartDate, radius, radiusUnit, selectedCategoriesFacet, selectedFlexFieldsFacets, selectedLocationsFacet, selectedOrganizationsFacet, selectedPostingDatesFacet, selectedTitlesFacet, selectedWorkLocationsFacet, selectedWorkplaceTypesFacet, siteNumber, sortBy, useExactKeywordFlag, userTargetFacetInputTerm, userTargetFacetName, workLocationCountryCode, workLocationZipCode, workplaceType. Other finders: findReqsByQRShortCode, findSimilarRequisitions, findSimilarRequisitionsByCandidate.
- The response root has `{count, hasMore, items, limit, links, offset, totalResults}`. items[0] is a search-state object holding TotalJobsCount, requisitionList[] and facet arrays (categoriesFacet, locationsFacet, postingDatesFacet, titlesFacet, …; each item is `{Id, Name, TotalCount}`).
- requisitionList attributes: Id, Title, PostedDate (date), PostingEndDate, PrimaryLocation, PrimaryLocationCountry, JobFamily, JobFunction, WorkplaceType(Code), ShortDescriptionStr, External{Qualifications,Responsibilities}Str (max 255 each), plus JobSchedule, JobType, ContractType, Department, LegalEmployer, Organization, BusinessUnit, HotJobFlag, TrendingFlag, Relevancy, Distance, Language, WorkerType. The children are secondaryLocations{CountryCode, GeographyId, Latitude, Longitude, Name, RequisitionLocationId}, otherWorkLocations, workLocation, primaryLocationCoordinates and requisitionFlexFields. NOT in the list: Category, ExternalDescriptionStr, ExternalPostedStartDate.
- `GET …/recruitingCEJobRequisitionDetails` finders: ById {Id, siteNumber}, ByIdNoCache, PrimaryKey {Id}. Attributes: Id, Title, Category, External{Description,Qualifications,Responsibilities}Str, ShortDescriptionStr, CorporateDescriptionStr, OrganizationDescriptionStr, ExternalPostedStartDate and ExternalPostedEndDate (date-time), PrimaryLocation(Country), JobFamilyId (no JobFamily string), JobFunction(Code), WorkplaceType(Code), NumberOfOpenings, RequisitionType, JobSchedule, JobType, JobGrade, JobLevel, HiringManager (PII: never emit), LegalEmployer, ContentLocale. Children: media, otherWorkLocations, primaryLocationCoordinates, requisitionFlexFields, secondaryLocations, skills, workLocation. There is NO PostedDate on the detail; use ExternalPostedStartDate.
- Finder syntax: `finder=<name>;var=value,var2=value2`. String values in double quotes, with `\` and `"` escaped by a backslash; the detail Id must be quoted (headstart: an unquoted id gave 400). Several values inside one variable are separated by `;` (URL-encoded %3B). The official OpenAPI document is https://docs.oracle.com/en/cloud/saas/human-resources/farws/openapi.json (not fetched).
- Query params: expand ("all" or a child list; Child.NestedChild), fields (cannot be combined with expand; fields wins), onlyData, limit, offset, totalResults, orderBy, q.

## Behaviour from clients (with URLs in the agent report)
- PAGING GOES INSIDE THE FINDER: top-level ?limit/?offset are silently ignored, so every page returns the same 25 (jobseek KB; kalil0321). VERIFIED-HERE: limit=25 inside the finder returned 25.
- `expand` MUST include requisitionList, or the list is empty while the count is correct (kalil0321, career-ops, fetchaller).
- Max limit is 200; larger values echo 200 (headstart, 8 Sep). Offset ceiling: offset+limit <= 10000, and beyond it you get 0 rows AND TotalJobsCount 0 (headstart; jobseek _RESULT_WINDOW_LIMIT). Not relevant at about 600 postings.
- STOP ON AN EMPTY PAGE, not on a short page, and do not trust hasMore. hasMore was false at a total of 248; one tenant returned 199 of 420 at offset 0 (headstart; kalil0321: 198 instead of 200).
- Always send sortBy=POSTING_DATES_DESC. The unsorted default order is not stable across offsets (amikai). POSTING_DATES_ASC exists (headstart ADR-0239). RELEVANCY and DISTANCE are INFERRED UI tokens; VERIFIED-HERE, the default echo was SortBy "RELEVANCY".
- TotalJobsCount is mostly exact (85.3% of 245 boards landed on it, and the shortfalls were over-counts). Some tenants repeat rows within a page, so dedupe by Id.
- The listing never carries ExternalDescriptionStr, even with expand=all. ShortDescriptionStr is capped at 1,000 chars where present (VERIFIED-HERE: empty on 25/25 Uber rows). The detail has ExternalDescriptionStr on 93.1% of payloads. In the listing, Department, JobFunction and JobType are 0% non-null (VERIFIED-HERE for Uber).
- Detail for an unknown or expired id returns 200 with `items: []`, so a typed not-found is needed. siteNumber is ignored on detail calls (headstart).
- A WRONG siteNumber is NOT rejected: the listing returns the host's whole job set. Read the real one from `<base data-apibaseurl data-sitenumber>`. VERIFIED-HERE: CX_1 from the UberCareers page; it returned TotalJobsCount 578, which matches jobs.uber.com's HTML 578.
- Headers: a browser User-Agent is required (python-requests/X gets 403, per AgentWong). Optional Accept-Language: en and Ora-Irc-Language: en. No auth, cookies or CSRF.
- Country filter: workLocationCountryCode takes ISO2 in every sample. It is unclear whether it matches the primary location only or any location; kaamilbadami retries without it, so it may be unreliable (INFERRED). selectedLocationsFacet takes numeric geography ids from locationsFacet[].Id, and the response echoes SelectedLocationsFacet, so a client can check the filter applied. The `location` keyword-ish filter takes country names and ignores cities (fetchaller: "Canada" 640→13).
- Multi-location: PrimaryLocation plus secondaryLocations[] (expand requisitionList.secondaryLocations) and otherWorkLocations/workLocation.
- Blocking reports: 503 bursts (jobseek #2217, Apr 2026); transient 302s (#5715, Jul 2026); intermittent Akamai 403s on valid requests (Albertsons tenant, #6394, Aug 2026); a WAF blocking datacenter IPs on some tenants (career-ops). headstart: no rate limit seen, 6,351 requests with 0 non-200s, no ratelimit or retry-after headers.
