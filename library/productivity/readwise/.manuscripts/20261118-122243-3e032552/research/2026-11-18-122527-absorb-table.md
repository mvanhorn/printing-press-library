### Auth & endpoint ground truth

From source read via `gh api` (Step 1.5a.5).

**Auth header and env vars**
- `Authorization: Token <token>` (note `Token`, not `Bearer`) in: readwise-mcp-enhanced `src/readwise-client.ts` (`'Authorization': \`Token ${this.token}\``), ngpestelos (`"Authorization": f"Token {READWISE_TOKEN}"`), kiseki, IAmAlexander `src/api/client.ts`. Matches the brief.
- Env var names are NOT standard across tools: `READWISE_TOKEN` (readwise-mcp-enhanced, ngpestelos), `READWISE_API_KEY` (IAmAlexander), `READWISE_ACCESS_TOKEN` (tcnksm), `READER_API_TOKEN` (Scarvy rw-cli), `READWISE_TOKEN` (floscha). We keep `READWISE_API_TOKEN` per the brief; consider accepting `READWISE_TOKEN` and `READWISE_ACCESS_TOKEN` as fallbacks (build decision, not a contradiction).
- Official hosted MCP uses OAuth through the MCP gateway; the official CLI stores creds in `~/.readwise-cli.json` and also supports token login (token from https://readwise.io/access_token). The deprecated original readwiseio/readwise-mcp uses a different, private route: header `X-Access-Token` against `POST /api/mcp/initialize` and `POST /api/mcp/highlights` (not the public REST API); do not copy.

**Endpoints actually called (verified in readwise-mcp-enhanced `src/readwise-client.ts`; v3 base `https://readwise.io/api/v3`, v2 base `https://readwise.io/api/v2`, auth probe `GET https://readwise.io/api/v2/auth/`)**
- v3: `POST /save/`, `GET /list/` (query: id, updatedAfter, location, category, tag, pageCursor, withHtmlContent), `PATCH /update/{id}/`, `DELETE /delete/{id}/`, `GET /tags/`.
- v2: `GET /highlights/`, `POST /highlights/`, `GET /export/` (updatedAfter, ids, includeDeleted, pageCursor), `GET /review/`, `GET /books/`.
- Other real v2 paths seen: `GET|POST /highlights/{id}/tags`, `PATCH|DELETE /highlights/{id}/tags/{tag_id}`, `/books/{id}/tags` (kiseki `src/readwise_mcp/tools/readwise/manage_tags.py`); `POST /highlights/` (Zotero2Readwise).
- tcnksm/go-readwise-reader and Scarvy/readwise-reader-api hit v3 `save`/`list`/`update`/`delete`; Scarvy lists save params url, html, shouldCleanHtml, title, author, summary, publishedDate, imageUrl, location, category, savedUsing, tags.
- 429 handling: read `Retry-After` header (seconds), fallback 60s (readwise-mcp-enhanced). Matches the brief.
- Page sizes: highlights `page_size` up to 1000 (enhanced default 100, getBookHighlights uses 1000).

**Response fields actually selected (high-gravity)**
- Documents (enhanced `document-handlers.ts`, `tag-search-handlers.ts`): id, url, title, author, source, category, location, tags, site_name, word_count, created_at, updated_at, published_date, summary, image_url, source_url, notes, reading_progress, first_opened_at, last_opened_at, saved_at, last_moved_at; html_content only on request. Official `response_fields` list adds reading_time, content, parent_id, is_deleted.
- Tags: `{name, key}`.
- Daily review: review_id, review_url, highlights[].
- Highlights/books: count, results[]; export returns books with nested highlights.

**Contradictions or cautions versus the brief/spec**
