## Generation phase (Phase 2) — issues found and fixed

1. **Naming collision: `analytics values` vs. reserved framework `analytics` command.** The novel-features subagent proposed `analytics values --dept <name>`, but `analytics` is a reserved generator-provided top-level command (generic count/group-by/summary tool over synced data). The generator correctly detected the collision and silently skipped wiring `newNovelAnalyticsValuesCmd` — no `AddCommand` call was emitted anywhere, leaving the file orphaned. Confirmed via `grep` for the constructor name across `internal/cli/`. Fixed by renaming to `recognition values` (also a better fit — it's computed from the same synced recognition feed as `recognition audit`/`recognition gap`). Updated in `research.json`, the absorb manifest, and noted (not rewritten) in the brainstorm audit trail.

2. **`which_test.go`'s `TestWhichIndex_ExistsAndIsWellFormed` failed for 3 of 6 novel features** (`recognition audit`, `recognition gap`, and the pre-rename `analytics values`). Root cause, confirmed by direct binary execution (`recognition audit --help`, `recognition gap --help` both resolve correctly with exit 0 and correct flags) and by reading the generated test source: the test calls Cobra's raw `root.Find(strings.Fields(e.Command))` and asserts `len(remaining) == 0`. Cobra's `Find()` reliably strips only persistent/inherited flags during tree descent, not leaf-local flags registered via `cmd.Flags()` — so any `research.json` `novel_features[].command` value containing a leaf-local flag (`--dept engineering`, `--manager me`) will always leave that flag in `remaining`, regardless of `=`-form vs space-form (tested both; no difference). This is partly a real authoring mistake on my part: `research.json`'s `command` field is documented as "the full command path," not a full invocation — flags belong in `example`, which I had already populated correctly and separately. Fixed by stripping flags from all three `command` fields (`recognition audit`, `recognition gap`, `recognition values`) and regenerating. Also worth a retro note: the test's brittleness against any local-flag example (even a spec-compliant one) is a real generator fragility that would trip up the next author who reads "full command path" more loosely.

3. **`validate-narrative --full-examples` caught a real path bug**: `narrative.quickstart`/`narrative.recipes` referenced a bare `feed` command. `feed` is an endpoint under the multi-endpoint `recognition` resource, not an auto-promoted bare command (only single-endpoint resources like `balance`, `company`, `incentives` get bare-promoted). The actual path is `recognition feed`. Fixed in `research.json`; also caught and fixed the same bare-vs-nested mistake for several other absorbed-manifest rows that predated actual generation (`me` -> `users me`, `company show` -> `company`, `incentive claim` -> `incentives <id>`, `redemptions list` -> `redemptions list-mine`) — these were planning-stage guesses made before the Cobra tree existed to check against.

4. **`sync --resources users` will hit `/users/bulk` (requires `ids`, no default) instead of `/users/search` (no required params) at runtime.** Confirmed via `sync --resources users --dry-run` showing the `/users/bulk` request both before and after reordering `search` above `get-bulk` in the spec's endpoint declaration order — reordering had zero effect, disproving my initial theory that sync picks the first-declared array-response endpoint. The actual heuristic appears to be alphabetical-by-endpoint-key (`get-bulk` < `search`). **Not fixed** — no spec-level lever was found to influence this within time budget, and it is non-fatal: a live sync would error out for the `users` resource specifically (missing required `ids`) while other resources (`recognition`, `departments`, `locations`, `org`, `balance`, `redemptions`) sync fine, since none of them have this same multi-array-endpoint-with-a-required-param shape in a way that picks the wrong one. None of the 6 transcendence features depend on `users` being synced (they read from `recognition`, `departments`, and `org` instead). Flagging as a Printing Press retro candidate: sync's endpoint-selection heuristic should prefer array endpoints with zero required params over ones with required params lacking defaults, not pick alphabetically.
