# 3CX Configuration API (XAPI) CLI Brief

## API Identity
- **Domain:** PBX / telephony system configuration & reporting for 3CX V20+. Programmatic control over nearly every part of a 3CX phone system via an OData v4 REST API at `/xapi/v1`.
- **Spec:** Official OpenAPI 3.0.4, served live by the instance at `https://<fqdn>/xapi/v1/swagger.yaml` (generated by Microsoft.OpenApi.OData). 297 paths, 589 operations (318 GET / 173 POST / 65 PATCH / 33 DELETE), 1052 schemas, 111 resource collections.
- **Users:** MSP/IT admins and integrators who manage one or many 3CX tenants. They live in the 3CX web admin console today and want scriptable, auditable, agent-driven access.
- **Data profile:** Highly relational config graph (DN/Users ↔ Groups ↔ RingGroups/Queues ↔ Trunks/DIDs/Rules ↔ IVRs) plus high-volume reporting views (CallHistoryView, ChatHistoryView, EventLogs, queue/agent statistics). Perfect for a local mirror + cross-entity queries.

## Auth
- **Type:** OAuth2 client-credentials. `POST /connect/token` (form-encoded, `grant_type=client_credentials`, `client_id`, `client_secret`) → Bearer token, `expires_in` 3600s, no refresh token. Token sent as `Authorization: Bearer`.
- **Canonical env vars (ecosystem convention):** `TCX_CLIENT_ID`, `TCX_CLIENT_SECRET`, `TCX_FQDN`. (Matches SSIG-IT/3cx-mcp-server; avoids leading-digit env-var problems.)
- **Critical gotcha:** The API client's Service Principal must have the **System Owner** role. "System Administrator" causes 403 on call history and several reporting endpoints. → Troubleshooting entry.
- **Token URL is origin-relative** (`/connect/token`, NOT under `/xapi/v1`). Base URL = `https://<fqdn>/xapi/v1`; token endpoint resolves against the host root.

## Reachability Risk
- **None.** Live instance `https://your-3cx-fqdn.example.com` confirmed reachable: `$metadata` 200, XAPI collections return 401 without token (auth-required-as-expected), `POST /connect/token` returns 400 for missing creds (endpoint live). Spec fetched directly from the instance.

## Users (personas)
1. **The MSP onboarding engineer** — stands up new 3CX tenants for clients. Bulk-creates extensions, groups, ring groups, queues, inbound/outbound rules, and DID routing. Today: clicks through the web console hundreds of times per tenant, or copies a "golden" tenant by hand. Cannot diff two tenants or replay a known-good config.
2. **The IT admin / helpdesk lead** — owns one in-house 3CX. Daily reality: "extension 214 isn't ringing," "why did this DID stop routing," "did someone change the after-hours rule." Today: hunts across Users, RingGroups, InboundRules, OfficeHours screens. No single view, no change history, no "what changed since yesterday."
3. **The contact-centre supervisor** — cares about queues. Daily ritual: check queue SLA, abandoned calls, agent login/idle, callbacks. Today: 3CX's reporting screens are slow, siloed per-queue, and don't roll up across queues or compare week-over-week.
4. **The security/compliance admin** — reviews the PBX attack surface. Checks blocklist, blacklisted numbers, anti-hacking settings, failed-auth events, admin audit log. Today: scattered across Security and Logs screens with no consolidated posture report.

## Top Workflows
1. **Audit the config graph** — "show me every ring group / inbound rule / IVR destination that points at a deleted or disabled extension/DID." Cross-entity integrity check the console can't do.
2. **Snapshot & diff** — capture the full PBX config, then later show exactly what changed (extensions added/removed, trunk edits, rule changes, office-hours edits). Change management / drift detection.
3. **Bulk provision** — create N extensions/users from a CSV idempotently, with `--dry-run`, assign groups & roles. Onboard a tenant in one command.
4. **Queue/agent performance rollup** — one command joining queue performance, agent-in-queue stats, abandoned calls, and SLA breaches across all queues, filterable by window.
5. **"What changed / what's wrong now"** — time-windowed merge of activity log + event logs + active calls + system status to answer "what's happening on this PBX right now / since 2h ago."
6. **Search everything offline** — FTS over the local mirror (users, groups, ring groups, queues, trunks, DIDs, contacts) by number or name, instantly, without paging the live API.

## Table Stakes (must match the incumbents)
From **getrav/3cx-cli** (Python, the closest competitor) and **SSIG-IT/3cx-mcp-server** (TypeScript MCP, 22 tools):
- Users: list / get / create / update / delete; assign role; departments(Groups) CRUD.
- Active calls (list + drop); call history with date/OData filters; recordings (list/download/delete).
- Queues, RingGroups, Receptionists(IVRs): list/get (incumbents are read-only here — we go full CRUD where the API allows).
- Trunks list/get/detail; phones/SipDevices inventory; contacts (search/export/delete).
- Inbound/Outbound rules; parking; DID numbers; office hours; holidays.
- System status; backups (create/restore); restart (guarded); emergency numbers/E911.
- Security: blacklist numbers, IP blocklist, activity/audit log with severity filter.
- OData query flags on lists: `$top/$skip/$filter/$select/$expand/$orderby/$search/$count`.
- Forwarding profiles get/set; extension status/registration.
- Token auto-refresh (60-min lifetime).

## Data Layer
- **Primary entities to mirror:** Users (DN), Groups, RingGroups, Queues, Receptionists, Trunks, Peers, InboundRules, OutboundRules, DidNumbers, OfficeHours, Holidays, Parkings, Contacts, SipDevices/Phones, Sbcs.
- **Reporting views (sync-on-demand, time-windowed):** CallHistoryView, ChatHistoryView, EventLogs, ActivityLog, queue/agent statistics.
- **Sync cursor:** OData `$filter` on timestamps for history views; full snapshot for config entities. `LastCdrAndChatMessageTimestamp` endpoint gives an incremental cursor for call/chat history.
- **FTS/search:** offline FTS5 across config entities by Number, Name, Email, extension.

## Product Thesis
- **Name (slug):** `3cx-xapi` · binary `3cx-xapi-pp-cli` · display "3CX".
- **Why it should exist:** Every 3CX admin tool today covers a thin slice of the API and treats the PBX as a live thing you poke one object at a time. No tool mirrors the *whole* config locally, lets you search/query/diff it offline, audits cross-entity integrity, or speaks agent-native JSON. This CLI covers all 111 collections, adds a local SQLite mirror, offline search, config snapshot/diff, integrity auditing, queue analytics rollups, and bulk provisioning — turning the PBX into something you can script, version, and reason about.

## Build Priorities
1. **Foundation:** OAuth2 client-credentials token lifecycle; configurable base URL via `TCX_FQDN`; SQLite mirror + sync + FTS + SQL for all config entities; OData query flags wired through list commands.
2. **Absorb:** the full table-stakes surface above (and beyond — every generated endpoint command across all 111 collections), with `--json`, `--select`, `--dry-run`, typed exit codes.
3. **Transcend:** config snapshot/diff, cross-entity integrity audit, queue/agent performance rollup, "what changed since", bulk provision from CSV, security posture report, offline directory search. (Finalized by the novel-features subagent.)
