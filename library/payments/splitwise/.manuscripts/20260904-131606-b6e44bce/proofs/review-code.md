[MAJOR] internal/cli/{activity,audit,net,normalize,report,fairness,forecast,reconcile,resolve,split,fairness_nudge}.go (`flags.printJSON`) + brief.go (`printJSONFiltered`) — `--csv` output — These 12 commands route through `printJSONFiltered` → `printOutputWithFlags` → the 4.31.7 `printCSV`. Contract that changed: framework-delta lines 907-915 show 4.31.6 `printCSV` did `if err := json.Unmarshal(data, &items); err != nil { // Single object or invalid JSON - just print as JSON`; 4.31.7 `helpers.go:2727-2741` `tabularObjectRows` ends with `return []map[string]any{obj}, true` (an object with ≥2 non-metadata arrays, or no arrays, becomes ONE row), and `helpers.go:2577` `writeCSVRows` renders every non-float cell with `fmt.Sprintf("%v", v)`, so nested maps print as `[map[to_id:4.5142496e+07 …]]`. Verified on the store copy: `net`, `audit`, `activity`, `normalize`, `report` each emit a 1-row CSV containing `map[` cells, and the numeric tokens include `1.306681189e+09`, `4.668104764e+09`, `1.07803424e+08` — Splitwise expense/user ids in scientific notation, which the brief lists as an API truth that must never happen. Yesterday's 4.31.6 binary (`~/go/bin/splitwise-pp-cli` 2.0.0) prints the JSON document for the same invocation, so this is a regression shipped by the framework delta, exactly the defect the new fallback in splitwise_output.go:25-30 was written to avoid — but that fallback only runs for the 5 `emitStructured` callers (balances, ledger, recurring, settle_up, spend). Failure scenario: `splitwise-pp-cli net --csv > net.csv` → one unparseable row, ids corrupted. Fix: make `emitStructured` the single hand output path — replace `flags.printJSON(cmd, v)` / `printJSONFiltered(cmd.OutOrStdout(), v, flags)` at those 14 call sites with `flags.emitStructured(cmd, v)` (identical `--json`/`--agent` behavior since `emitStructured` ends in `f.printJSON`), and add one test asserting `net --csv`/`audit --csv` on a fixture store contains no `map[` and no `e+0`. File a machine retro: 4.31.7 `printCSV` flattens objects and `%v`-formats nested float64 ids (the CDR at docs/demo-runbooks/splitwise.cdr.md:1376-1377 documents the old "object → JSON fallback" as the contract).

## Biggest risks
1. `--csv` on the 12 non-`emitStructured` commands ships corrupted ids and unparseable rows (Major above); an agent or script that exported `net --csv` under 2.0.0 gets a silently different, wrong file under this build.
2. Inconsistent `--json` error surface across the novel commands (Minor) will keep surfacing in reviews until every typed return goes through `novelErr`.
