# Privacy review — splitwise reprint 4.31.6 → 4.31.7 (2026-09-04)

Reviewer: independent privacy engineer (second opinion). Scope per brief: hand delta `3f92465..b81bb3b`, framework delta 4.31.6→4.31.7, fixtures. Yesterday's closed findings not re-raised (none regressed). Real store touched READ-ONLY via `sqlite3 … mode=ro&immutable=1`, counts only — no value from it appears here.

## Verdict
Privacy-sound to ship — no Critical/High; the framework delta adds no new disclosure, on-disk artifact, or log line carrying resource JSON, and the hand delta's `--csv` JSON fallback is data-equivalent to `--json`. Two pre-existing MEDIUM minimization gaps (a `--select` miss echoes the whole payload; hand `--csv/--plain` ignore `--select`) are recommended fixes, not blockers.

## Data-flow & PII map (brief)
- Subjects: the account holder (id, name, email, default currency) and every friend/group member (third parties who never interact with this tool): first/last name, email (56/56 friends in the real store carry one — count only), per-currency balances, group memberships; expenses: description, cost, per-user paid/owed shares, dates, deleted_at; notifications: HTML `content` naming people; comment text (`fairness nudge --message`).
- Store: `~/.local/share/splitwise-pp-cli/data.db` (`resources(resource_type,id,data)`, all seven types, full API JSON). Plus the HTTP response cache `<cache>/resources/*.json` (0600, full GET bodies, 5-min TTL, never swept) — `client.go:676-692`.
- Egress: stdout (json/csv/plain/quiet/agent envelope) → terminal, pipes, MCP shell-out capture (`cobratree/shellout.go:323-351`) → LLM context; stderr hints (`hint:`/`warning:` lines only) → second MCP content block; live API writes (`/create_expense`, `/create_comment`) gated by `--record`/`--send` + harness refusal; `--deliver file|webhook` (opt-in, blocked from MCP via `blockedRootFlags` `shellout.go:209-220`).
- Deletion: none new; store rows persist until the API stops returning them (deferred yesterday); cache files persist past TTL.

## Findings

[MEDIUM] `internal/cli/helpers.go:1938-1942` — `--select` miss → full payload. `filterFields` prints `warning: --select %q matched no fields; valid fields: …` then `return data` unfiltered. Path: `get-friends --agent --select nmae` (typo) or an agent calling the MCP mirror with a wrong field → all 56 friends incl. emails into the LLM context although one field was requested. The warning is forwarded as an MCP hint (`shellout.go:353-365`) but the payload still lands. Subjects: every friend. Unchanged from 4.31.6 (filterFields not in the delta) — NOT a regression, generator behaviour; yesterday's README audit hit the same symptom on a recipe. Remediation (machine retro): on an anchored total miss emit the empty shape (`[]`/`{}`) plus the warning, never the unfiltered document. (GDPR Art. 5(1)(c) minimisation; agent-context boundary.)

[MEDIUM] `internal/cli/splitwise_output.go:22-32` — hand `emitStructured` `--csv`/`--plain` branches bypass `--select` and `--compact`. `printCSV(table)`/`printPlain(table)` are called on the raw projection; only the JSON branch (`f.printJSON` → `printJSONFiltered` → `printOutputWithFlagsMeta:2220-2223`) applies `filterFields`. Path: `ledger --friend X --csv --select date,delta` emits every column incl. `description` (`ledger.go:64-72`); same for the other `emitStructured` callers: `balances.go:59,143,284`, `recurring.go:268`, `settle_up.go:177,299,321`, `spend.go:116,282`. MCP forwards `select`/`csv` (not in `blockedRootFlags`), so an agent asking for two columns gets the whole row. Subjects: friends named in rows. Pre-existing — the prior library `splitwise_output.go` csv branch is identical — so not a 4.31.7 regression, but it was not closed yesterday. Remediation (hand, cheap): apply `filterFields(table, f.selectFields)` (and `compactFields` when `f.compact`) before `printCSV`/`printPlain`, or route the projected table through `printOutputWithFlags`. Add a test `TestEmitStructured_CSVHonoursSelect`.

[LOW] `internal/cli/helpers.go:2243-2245, 2644-2705` — `--quiet` semantics changed: 4.31.6 suppressed all output (`return nil`), 4.31.7 prints one identity value per row. For hand rows with no id/name key — `friendLedgerRow` (`ledger.go:64-72`: date, description, group, currency, delta, running_balance, payment), forecast/recurring rows — `quietRowValue` falls through to `for _, v := range item` (`helpers.go:2699-2703`), i.e. a randomly-ordered Go map, so `ledger --friend X --json --quiet` prints a nondeterministic field per row that may be the expense `description`. Also any script that used `--quiet` for silence (e.g. cron `sync --quiet >> log`) now writes output. Impact low (own data, user-invoked, local), and the documented contract (`root.go:337` "Bare output, one value per line") already said this, so it is a fix that surfaced a hand-side gap. Remediation: give hand rows an identity key (`expense_id`) so quiet is deterministic; generator retro: sort keys before the last-resort loop; CHANGELOG note on `--quiet`.

[LOW] `internal/cli/helpers.go:2333` + `promoted_get-friends.go:58,86` — `email` is a "compact gravity" field and a documented field of `get-friends`, so `--agent`/`--compact` (the agent defaults) keep every friend's email in the LLM-bound envelope; the typed MCP `get-friends_list` returns the full objects. Not new (4.31.6 kept all documented fields), and an API mirror arguably includes contact fields, but privacy-by-default compaction for third-party subjects would drop direct contact identifiers unless `--select email`. Generator retro. (Art. 25 by-default.)

[LOW] `internal/client/client.go:407-413, 676-692, 784-795` — `GetNoCache` "skips the cache read but still writes cacheable fresh responses"; settle-up's dedup pre-scan (`settle_up.go` hand-delta lines 697-713, `updated_after` 48h, `limit=200`) therefore persists up to 200 live expenses (descriptions, per-user shares) into `<cache>/resources/…json` on every `--record`. Files are 0600 and ignored after 5 min, but only removed on overwrite or explicit invalidation — expired snapshots accumulate with no sweep. Storage-limitation hygiene, pre-existing pattern. Remediation: `os.Remove` on an expired read, or a TTL sweep in `doctor`/startup. (Art. 5(1)(e).)

## Biggest privacy risks
1. Third-party friend emails and expense descriptions entering LLM context beyond what was asked: a `--select` miss (framework) or `--csv/--plain --select` on hand commands (hand) returns the unminimised row set. Both pre-existing; the hand one is a one-function fix.
2. Storage limitation in the response cache: full live expense pages written on every `settle-up --record` pre-scan and never swept.
3. Interface drift with privacy edge: `--quiet` now emits data (nondeterministic field for id-less hand rows) where scripts may have relied on silence.

## Genuinely privacy-respecting (incl. where a shallow checklist would wrongly flag)
- The `--csv` JSON fallback in `emitStructured` looks like "printing the whole payload" but is exactly the `--json` document — no extra data, and strictly better than the flattened one-row CSV.
- Warnings that list `valid fields` / `could not apply filter(s)` print field/parameter names, not values; MCP forwards only `hint:`/`warning:` stderr lines.
- MCP truncation is drop-in-memory with a bounded preview; no tmp/disk side channel; `--deliver`, `--audit-dir`, `--receipt-file`, `--token`, `--home`, `--config` are blocked from MCP callers.
- `writeDryRun` precedes every store read and carries no PII; write paths still gate on `IsAnyHarness()` (fairness_nudge.go:60-62, settle_up.go, split.go) — yesterday's fix intact.
- `upsertSingleObject` refusing non-JSON bodies and local-read filtering both reduce what is stored/returned relative to 4.31.6.
- Fixtures are synthetic (verified against the store by counts only); happy-args are `Example …` strings.
- Cache files 0600 in a 0700 dir; `ensureCachePerms` re-tightens leftovers.
- Yesterday's INFO/deferred items (receipts persist argv, webhook sink plaintext opt-in, deleted-expense retention, MCP write opt-in) are unchanged — not regressed, not re-raised.

## Missing controls / over-collection
- `--select` miss should fail closed to the empty shape (generator).
- Hand `emitStructured` csv/plain must honour `--select`/`--compact` (hand, this round if cheap).
- Deterministic `--quiet` for id-less hand rows (add `expense_id`), CHANGELOG note that `--quiet` now prints.
- Drop `email` from the default compact allow-list for third-party lists, or document `--select` as the way to get it (generator, privacy-by-default).
- TTL sweep / delete-on-expiry for the HTTP response cache; consider `NoCache` for write-path pre-scans so `--record` never persists a live page.
- No DPIA trigger: no new category of data, no new recipient; personal financial data of third parties remains local-first with opt-in egress.
