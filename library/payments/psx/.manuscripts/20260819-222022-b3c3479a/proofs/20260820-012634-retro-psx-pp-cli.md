# Printing Press Retro: PSX (Pakistan Stock Exchange)

## Session Stats
- API: psx (Pakistan Stock Exchange data portal, `dps.psx.com.pk` + `www.psx.com.pk`)
- Spec source: browser-sniffed (agent-browser HAR) + hand-authored internal YAML
- Scorecard: 98/100 (A)
- Verify pass rate: 97% (66/68, 0 critical)
- Live dogfood: 217/217, 0 failures
- Fix loops: 2 shipcheck loops + 1 polish pass + 1 code-review autofix pass
- Manual code edits: ~30 files (8 novel features, a sibling HTTP client, an HTML table parser, 20 regression tests)
- Features built from scratch: 8 transcendence commands + ~14 hand-authored absorbed commands

All findings below reproduce on `v4.31.0` and were verified against the generator's
own templates in the module cache, not inferred from behavior alone.

## Findings

### 1. `generate --force` lets a stale generated file win over a changed spec (Bug)
- **What happened:** After correcting `learn.ticker_patterns` in the spec, regeneration
  kept the *previous* `internal/cli/learn_init.go` verbatim. The corrected pattern never
  reached the CLI; the fix appeared not to work. Only deleting the whole working tree
  and regenerating clean produced the new value.
- **Scorer correct?** N/A (not a score finding).
- **Root cause:** `generator` — force-regen AST reconciliation classified a
  `// Generated by CLI Printing Press ... DO NOT EDIT.` file as drift worth preserving,
  so spec-derived content lost to a stale artifact.
- **Cross-API check:** Recurs on any spec edit whose value lands in a generated file —
  i.e. every reprint and every mid-run spec correction.
- **Frequency:** every API that is regenerated after a spec change.
- **Fallback if the Printing Press doesn't fix it:** The operator must know to delete the
  tree. I did not know; I spent a full debug cycle concluding my own edit was wrong.
  Fallback reliability is poor because the failure is *silent* — regen reports success.
- **Worth a Printing Press fix?** Yes. Silent wrong output, and it actively misleads the
  operator into distrusting a correct fix.
- **Inherent or fixable:** Fixable. A file carrying the DO-NOT-EDIT header has no
  hand-edits worth preserving by definition.
- **Durable fix:** In force-regen reconciliation, always overwrite files whose header
  marks them generated. Preservation logic should apply only to files lacking that marker.
- **Test:** positive — change a spec field that renders into a DO-NOT-EDIT file, regen,
  assert the new value is present. negative — hand-author a novel file with no generated
  header, regen, assert it is still preserved.
- **Evidence:** Corrected `^[A-Z][A-Z0-9]{1,11}$` to `^[A-Z0-9]{3,12}$` in the spec;
  `grep regexp.Compile internal/cli/learn_init.go` still showed the old pattern after two
  regenerations. Both the working tree and the `.preserve-` snapshot held the stale value.
- **Related prior retros:** None (first retro on this machine).

### 2. Generated learn test fails generation for any CLI whose ticker pattern matches a 2-char token (Bug)
- **What happened:** `go test ./...` — part of the generate validation gate — failed with
  `TestLearnEvents_AliasMediatedRecallCreditsTaughtRowID`. Generation aborted. My
  `learn.ticker_patterns` were domain-correct for PSX; the test fixture collided with them.
- **Scorer correct?** No. The CLI was fine; the emitted fixture is unsafe.
- **Root cause:** `generator` — `templates/teach_test.go.tmpl:871` uses the literal `"WC"`
  as an org alias (`for _, value := range []string{"WidgetCo", "WC"}`). Any spec whose
  ticker pattern matches `WC` causes the pattern extractor to claim the token before the
  lookup resolver can bridge the alias, so recall misses and the emitted test fails.
- **Cross-API check:** Recurs for any CLI with short uppercase identifiers — stock tickers,
  currency codes, airport codes, country codes, exchange symbols.
- **Frequency:** subclass: any CLI declaring `learn.ticker_patterns` that match 2-char
  uppercase tokens.
- **Fallback if the Printing Press doesn't fix it:** The operator must narrow a
  domain-correct pattern to appease a fixture. I did — and the narrowing happened to also
  be more correct here (PSX has no 2-char symbols), but that was luck, not design. A CLI
  with genuine 2-char identifiers would have to choose between a correct pattern and a
  passing build.
- **Worth a Printing Press fix?** Yes — it hard-fails generation for a valid spec.
- **Inherent or fixable:** Fixable; one fixture string.
- **Durable fix:** Change the emitted fixture alias to a token no plausible ticker pattern
  matches (e.g. a lowercase or punctuated alias like `widget-co`), or make the seeded
  pattern extractor defer to explicitly taught lookups.
- **Test:** positive — generate with `ticker_patterns: ["^[A-Z]{2,4}$"]` and assert
  `go test ./...` passes. negative — assert alias-mediated recall still works.
- **Evidence:** `templates/teach_test.go.tmpl:871`. Failure output showed
  `Normalized:"display quarterly report"` with `QueryEntities:[]` — `WC` was consumed as a
  ticker and never resolved as an alias.
- **Related prior retros:** None.

### 3. `verify-skill` and dogfood resolve command paths by leaf token, producing unfixable false-positive ship blockers (Scorer bug)
- **What happened:** `verify-skill` reported 3 `positional-args` errors claiming
  `watchlist show` declares `Use: "show <name>"` and `watchlist add` declares
  `Use: "add <name>"`. Both are false. The real commands declare `Use: "show"` (0 args,
  exits 0) and `Use: "add <symbol>..."` (variadic, exits 0 with three symbols). This kept
  the shipcheck umbrella red through the entire run.
- **Scorer correct?** No — proven two independent ways.
  (a) Renaming my commands to `prices`/`track` left the findings **byte-identical**, still
  citing `watchlist show`/`watchlist add` — so the check never reads my commands.
  (b) Renaming the placeholder `Use` strings in the CLI's own `internal/cli/platform_client.go`
  changed the **reported** string verbatim while still attributing it to `watchlist`.
- **Root cause:** `scorer` — command paths are resolved by leaf token, ignoring the parent
  group, and hook-registered commands are invisible to the static walk. The colliding
  strings come from `templates/profile.go.tmpl:335` (`Use: "show <name>"`) and
  `templates/platform_cli.go.tmpl:462,528` (`Use: "add <name>"` / `"show <name>"`) — both
  emitted into **every** printed CLI. In this CLI the `platform_cli` commands are not even
  registered in the Cobra tree.
- **Cross-API check:** Universal by construction. Any CLI with a subcommand group whose
  leaf is `show`, `add`, `list`, `search`, `delete`, or `use` collides with framework
  commands present in every generated CLI. Dogfood's novel-feature depth check fails the
  same way (`watchlist show` -> `profile show`, `docs search` -> `search`).
- **Frequency:** every API whose novel features are grouped subcommands.
- **Fallback if the Printing Press doesn't fix it:** None that isn't gaming. The available
  "fixes" are weakening `platform_cli`'s genuinely-required `ExactArgs(1)`, renaming
  correct manifest-approved commands, or deleting accurate README/SKILL recipes.
- **Worth a Printing Press fix?** Yes — it is a red shipping gate that no correct CLI can clear.
- **Inherent or fixable:** Fixable — resolve by full path, and walk the registered tree.
- **Durable fix:** Resolve doc-referenced command paths against the full command path
  (parent + leaf), and enumerate the runtime-registered tree (as `agent-context` already
  does) rather than statically scanning source for `Use:` literals.
- **Test:** positive — a CLI with `foo show` (0 args) and a framework `profile show <name>`
  must produce no finding. negative — a genuinely wrong arity in a doc example must still fail.
- **Evidence:** Two controlled renames, described above. `platform_cli` commands absent
  from `psx-pp-cli --help`.
- **Related prior retros:** None.

### 4. Two scorecard dimensions penalize correct CLIs by measuring the wrong input (Scorer bug)
- **What happened:** `mcp_token_efficiency` scored 7/10 and `terminal_ux` 9/10 with no
  achievable path to 10 that does not degrade the CLI.
- **Scorer correct?** No, for both.
  - **mcp_token_efficiency** (`internal/pipeline/mcp_size.go:495` `scoreMCPTokenEfficiency`,
    `:114` `estimateMCPTokens`) counts **all** string literals in `internal/mcp/tools.go`,
    including handler implementation strings no agent ever sees. Measured here: 12,772 total
    literal chars, of which only 6,613 (51%) are the tool-registration region. Agent-facing
    alone = **66 tokens/tool**, inside the 10/10 band (<=80). Scored total = **127
    tokens/tool** -> 7/10. Even deleting every description I wrote leaves 61 tok/tool, so the
    only way to reach 10 is to gut descriptions — which would tank `mcp_description_quality`.
  - **terminal_ux** (`scorecard.go:578` via `sampleCommandFiles:3527`) samples the first five
    `*.go` files in `internal/cli`, which includes `_test.go` files and non-command infra.
    Here it sampled `actions_test.go` and `auto_refresh.go`; neither has a `Short:`, so
    `hasQualityDescription` fails on both and costs a point. Both are generator-emitted:
    `templates/novel_feature_command_test.go.tmpl` (0 `Short:` occurrences) and
    `templates/auto_refresh.go.tmpl`.
- **Root cause:** `scorer` — both dimensions measure inputs outside the thing being scored.
- **Cross-API check:** Universal by construction. Every CLI has handlers in `tools.go`; every
  novel feature emits a `_test.go`; `auto_refresh.go` ships in every CLI.
- **Frequency:** every API. Worse for CLIs with richer handlers and early-alphabet novel commands.
- **Fallback if the Printing Press doesn't fix it:** None. The penalty is unearned and the
  only remedies degrade quality.
- **Worth a Printing Press fix?** Yes — it mis-scores, and it pressures agents toward
  actively worse CLIs.
- **Inherent or fixable:** Fixable; both are input-selection bugs.
- **Durable fix:** Score `mcp_token_efficiency` over the tool-registration region only
  (first `NewTool(` to the first handler `func`). In `sampleCommandFiles`, exclude
  `*_test.go` and require the file to contain a `cobra.Command` literal.
- **Test:** positive — a CLI whose registration region averages <=80 tok/tool scores 10
  regardless of handler size; a CLI with five well-described command files scores full
  terminal_ux even when test files sort early. negative — a genuinely bloated registration
  region still scores low.
- **Evidence:** Measurements above, computed directly from the shipped `tools.go` and by
  simulating `sampleCommandFiles` against the library CLI.
- **Related prior retros:** None.

### 5. `response_format: html` silently returns wrong output for table endpoints (Template gap)
- **What happened:** PSX serves most of its useful surfaces as `<table class="tbl">` AJAX
  fragments. With `response_format: html` the only extraction modes are
  `page | links | embedded-json`, so generated commands returned page/link metadata instead
  of rows — `market watch` emitted a `links` array, and `history` returned `{}`. No warning.
- **Scorer correct?** N/A.
- **Root cause:** `generator` — no table extraction mode, and `cliutil` ships no table parser.
- **Cross-API check:** Recurs for any HTML-derived CLI whose payload is tabular. Named with
  evidence from the public library registry: **1688** (reverse-engineered wholesale search),
  **daraz** (product search + local price database), **alltrails** ("live-capable route map
  for AllTrails browser/mobile surfaces"), **boardgamegeek** (rankings/collections).
- **Frequency:** subclass: browser-sniffed CLIs over table-rendering sites.
- **Fallback if the Printing Press doesn't fix it:** The agent hand-authors a parser, as I
  did. That is real work (~14 of 37 absorbed features here) and it is *dangerous* work: my
  first parser ignored `colspan`/`rowspan` and mis-keyed every cell on PSX's two-level
  bid/ask depth header — the symbol landed under `volume` and bid price under `volume_2`.
  That is wrong-but-plausible numeric output, caught only by code review.
- **Worth a Printing Press fix?** Yes, primarily for the silent-wrongness. Even without a
  table mode, emitting *link metadata for a table endpoint with no warning* is a defect.
- **Inherent or fixable:** Fixable.
- **Durable fix (two tiers):** (a) minimum — when `html_extract.mode: page|links` is applied
  to a response that is predominantly a table, warn at generate time or refuse. (b) fuller —
  add `html_extract.mode: table` keying rows by `<th>` text. **If (b) lands it must expand
  `colspan` and carry `rowspan` forward**, or it reproduces the mis-keying bug above at
  machine scale.
- **Test:** positive — a table fragment yields header-keyed rows, including a two-level
  `colspan`/`rowspan` header. negative — a non-table HTML page still uses `page` mode.
- **Evidence:** `market watch --json` returned `{"results":{"links":[...]}}`;
  `history get --json` returned `{"results":{}}`. Live verification after the hand-authored
  fix: `board REG main` yields `bid_vol, bid_price, offer_vol, offer_price`.
- **Related prior retros:** None.

### 6. Printed CLIs assert things about themselves that are not true (Bug)
- **What happened:** Two independent false self-descriptions shipped in a CLI with no auth
  and no write surface:
  - `SKILL.md` told agents "Stored secrets live in `credentials.toml` under the data dir"
    and listed cookies/auth sidecars. `grep -r credentials.toml internal/` returns nothing
    and `doctor` reports auth "not required". The README/SKILL also carried create/write,
    `--stdin`, and mutation-confirmation guidance for a strictly read-only CLI, and the
    cache-freshness "Covered paths" block advertised `<resource> get|list|search` paths that
    do not resolve.
  - `.meta.source` is hardcoded to `"local"` and never reports `"live"`, including under
    `--data-source live` on an empty store — while the SKILL documents it as a provenance signal.
- **Scorer correct?** N/A.
- **Root cause:** `generator` — `templates/skill.md.tmpl:226,365,366` emit credential prose
  unconditionally; `templates/helpers.go.tmpl:2622` and `templates/mcp_tools.go.tmpl:1244`
  hardcode `map[string]any{"source": "local"}`.
- **Cross-API check:** The credential prose affects every no-auth CLI. Named with evidence
  from the public library registry: **coingecko** ("Free tier, no API key required for basic
  endpoints"), **docker-hub** ("Docker Hub public API"), **greenhouse** ("query any company's
  public Greenhouse job board"), **luma** ("no account, no API key"). The `meta.source`
  hardcode affects every CLI.
- **Frequency:** credential prose — subclass: no-auth CLIs; `meta.source` — every API.
- **Fallback if the Printing Press doesn't fix it:** An agent must audit generated docs
  against the binary. I only caught these by dispatching a dedicated docs-correctness review.
- **Worth a Printing Press fix?** Yes. These are agent-facing instructions that are false;
  an agent acting on them looks for a credentials file that does not exist, or routes on a
  provenance value that never varies.
- **Inherent or fixable:** Fixable — both are conditional-emission gaps.
- **Durable fix:** Gate the credential/mutation prose on `auth.type != none` and on the
  presence of mutating endpoints. Populate `meta.source` from the strategy actually used
  (live / local / cache) instead of a literal.
- **Test:** positive — generate a CLI with `auth: {type: none}` and no mutating endpoints;
  assert SKILL contains no `credentials.toml` and no write/`--stdin` guidance. positive —
  a live-served response reports `meta.source: "live"`. negative — an auth'd CLI keeps its
  credential section.
- **Evidence:** `skill.md.tmpl:226`, `helpers.go.tmpl:2622`, `mcp_tools.go.tmpl:1244`;
  docs audit verified `meta.source` was `local` across indices, announcements, docs search,
  basis and actions, including under `--data-source live`.
- **Related prior retros:** None.

## Anti-patterns
- **Chasing a score into a worse CLI.** Enabling `mcp.orchestration: code` to lift MCP token
  efficiency *lowered* the total 96 -> 93 (MCP Quality 10 -> 8; Desc Quality and Token
  Efficiency became N/A). Reverted. Recorded so it is not retried.
- **Trusting a green structural gate as behavioral proof.** `go build`, `verify`, and a Grade-A
  scorecard all passed while `basis` would have computed futures spreads from bid *volumes*.
  Only an adversarial code review caught it.
- **Assuming a failed fix means the fix was wrong.** The `learn_init.go` preservation bug made
  a correct spec edit look ineffective through two regenerations (F1).
- **Snapshot-then-destroy helper scripts without an existence check.** A rebuild helper wiped
  its own backup after a prior failed generate had already removed the source tree.

## What the Printing Press Got Right
- **The `.preserve-` snapshot saved the run.** When a failed `generate` left the output dir
  deleted and my helper wiped its own backup, the generator's snapshot still held every
  hand-authored file including the in-flight code-review fixes.
- **The novel-features subagent produced a genuinely strong manifest** — 7 survivors from 16
  candidates with an explicit killed-candidate audit trail; the kills (cost-basis portfolio,
