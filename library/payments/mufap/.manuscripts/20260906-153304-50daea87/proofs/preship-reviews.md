# MUFAP CLI — pre-ship reviews (Phases 4.8 / 4.85 / 4.9 / 4.95)

## skill-semantics — 4 error, 6 warning

### [ERROR]
L126 — `freshness` capability description is semantically wrong. SKILL.md says "Detect funds whose published NAV validity date lags **the requested date**." There is no requested date: `freshness --help` shows only --limit, --min-lag-days, --tab (no --from/--to/--date), and its long help states the opposite measurement — "Lag is measured against the newest validity date in the response, never against wall-clock time, so the output is reproducible." The shipped top-level one-liner is "Audit how stale MUFAP's default latest-available-per-fund view is." Ran `freshness --agent`: rows carry {fund, category, validity_date, lag_days} with lag_days relative to the newest validity date in the response (e.g. lag_days 211 for validity_date 2026-02-08). An agent reading the SKILL will believe it can/should pass a date and will misread lag_days as a lag against a date it chose.

### [ERROR]
`freshness` SUMMARY IS ARITHMETICALLY IMPOSSIBLE — TWO COUNTS OVERLAP AND OVERFLOW THE UNIVERSE. Repeated stably across runs: rows_with_validity_date 551, forward_dated_funds 42, lagging_funds 529. 42 + 529 = 571 > 551.
