# Review findings for internal/cli/universe.go

[MAJOR] Machine-output schema is not stable across the empty paths. $HOME/printing-press/.runstate/personal-74f0f171/runs/20260906-153304-50daea87/working/mufap-pp-cli/internal/cli/universe.go:178 and :198 emit `printJSONFiltered(..., make([]universeRow, 0), ...)` — a bare top-level JSON array `[]` — while the success path at :308 emits the `universeView` object `{"summary":{...},"rows":[...]}`. One command therefore returns two different top-level JSON types depending on whether the mirror file exists (:175) or the DB exists without the MUFAP schema (:195). The contract requires the summary (first_date, last_date, min_fund_count, max_fund_count, mean_fund_count, dates) to be emitted; on both empty paths none of it is, so an agent reading `.summary.min_fund_count` — the entire reason this command exists — hits a type error rather than an empty-but-shaped envelope. This is an explicitly commented invariant elsewhere in the package: panel.go:141-152 defines `panelEmpty()` with the comment "Shaped like a populated result so a machine caller parses one schema whether or not the mirror exists yet" and returns that same `panelView` at both panel.go:157 and :182. Fix: return `universeView{Summary: universeSummary{Resource: resource, From: flagFrom, To: flagTo, By: strings.ToLower(strings.TrimSpace(flagBy))}, Rows: make([]universeRow, 0)}` from both guards. (coverage.go:179 and rates.go:110 legitimately return bare slices because their success paths are also slices — universe's is not.)

[MINOR] No positional-argument rejection. universe.go:92-95 is `if len(args) == 0 && cmd.Flags().NFlag() == 0 { return cmd.Help() }` and nothing later inspects `args`. So `mufap-pp-cli universe daily-nav` — a natural mistake, since `daily-nav` is exactly a legal `--resource` value — has len(args)==1, fails the help guard, and runs to completion against the default `daily-returns`, reporting the wrong resource's universe width with no warning at all. The sibling command has the guard this file is missing: coverage.go:125-128 does `if len(args) > 0 { _ = cmd.Usage(); return usageErr(fmt.Errorf("coverage takes no positional arguments; got %q", args[0])) }`, placed after dryRunOK, which is the correct slot here too (after :98).

[MINOR] False all-clear when the mirror covers only a sliver of the requested window. universe.go:334-336 prints "width is constant across this window; cross-sectional stats are like-for-like" whenever `summary.WidthSpread == 0`. Dates with no stored rows never enter `widths` (:233-256), which is the right call — a fetched-and-empty or never-fetched date must not be counted as zero width — but it also means the branch fires on a window where the mirror holds 2 dates out of the 200 the user asked for. For the one command whose stated job (:39-42, README.md:217) is to stop a silently narrowing universe from faking a cross-section, affirmatively telling the human the window is like-for-like is the same failure mode inverted. The evidence is already in the struct — `summary.From`/`To` (requested) versus `FirstDate`/`LastDate` (actual) — but the human branch never compares them. Either qualify the sentence with the dates-seen-vs-requested count, or suppress the like-for-like claim when `--from`/`--to` were given and FirstDate/LastDate do not span them.

[MINOR] Annotations map at universe.go:88-91 omits `"pp:data-source": "local"`. The file-header comment at universe.go:2 (`// pp:data-source local`) satisfies the AGENTS.md requirement, but every other local-only reader also mirrors the value into the Cobra annotations map — coverage.go:113, panel.go:70, rates.go:57, export.go:86 — and agent_context.go:192 surfaces Cobra annotations to agents by design ("Surface Cobra annotations (e.g., pp:endpoint, mcp:read-only)"). As written, `universe` is the one local-store command that reads as source-unclassified in agent context output. The two contract-required annotations are correct: `mcp:read-only: "true"` (:89) and `pp:happy-args: "--from=2026-09-01;--to=2026-09-04"` (:90) matches the contract string exactly; `pp:typed-exit-codes` is correctly absent (no read-only sibling declares it).

[MINOR] Shipped docs advertise a field this command never emits. README.md:260 and the identical SKILL.md:210 give the flagship recipe `mufap-pp-cli universe --from 2016-01-01 --to 2026-09-04 --agent --select date,fund_count,sector` under the heading "Check universe width before any cross-section". universe.go emits the grouping column as `group`/`group_count` (struct tags at universe.go:35-36), and only when `--by` is passed (:284-295) — which the recipe omits. Copy-pasted verbatim, `--select` (helpers.go:1818 -> filterFields) projects away everything but date and fund_count and the sector dimension vanishes silently, with no error. Should read `--by sector --select date,fund_count,group,group_count`.
