# Review findings for internal/cli/export.go

[MAJOR] Contract violation: "Stream output — do not build the whole dump in memory before writing" is not satisfied. export.go:197 (`obs, err = store.LoadMUFAPObs(ctx, s, resource, flagFrom, flagTo)`) and export.go:186 (`store.LoadMUFAPCoverage`) both return a fully materialized slice — internal/store/mufap_schema.go:143 documents this explicitly ("Rows are drained fully before return") and :164/:174 accumulate every row, including each row's full `payload` JSON string, into `out` before returning. Only the *writing* is streamed (exportForEach at :259); the source set is entirely in RAM first. A multi-year daily-returns dump (hundreds of funds x thousands of dates) is held whole before the first byte reaches stdout, which is exactly the failure mode the clause guards against for a bulk load into an external research DB. Two supporting symptoms at specific lines: (a) export.go:193 and :204 apply --limit by slicing *after* the full load, so the contract's own happy-args case (`--limit=5`) still reads and materializes the entire table — the store loader takes no LIMIT and none is pushed down; (b) the comment at export.go:257-258 ("flattening one at a time so no full dump is ever materialized") asserts the contract is met when it is not, so the gap is easy to miss on a later read. Fix requires a callback/iterator reader in internal/store (e.g. ScanMUFAPObs(ctx, s, resource, from, to, limit, func(MUFAPObs) error)) with the limit pushed into SQL, with exportForEach driving it directly. Note the CSV path at :379-393 walks the rows twice (union header pass, then the write pass), so a streaming reader must be re-runnable rather than a one-shot channel.

[MINOR] export.go:161-163: the missing-mirror guard emits a JSON array (`printJSONFiltered(..., make([]exportRow, 0), ...)`) in the machine branch regardless of --format, so a consumer piping `export daily-returns --format csv` gets `[]` instead of a CSV header row, and a JSONL consumer gets an array document instead of zero lines. The zero-rows-but-mirror-exists case takes the other path and emits nothing at all (jsonl, :405) or a bare header (csv, :389), so the two empty cases produce three different document shapes. The house pattern in coverage.go:176-179 is being followed literally here, but coverage.go's body output is a JSON array while export's is not — the guard should emit the empty dump in the selected --format instead.

[MINOR] export.go:418-419: the machine branch returns `exportDump(out)` directly rather than routing through printJSONFiltered, so every root machine-output flag that `wantsMachineOutput` recognizes (helpers.go:2500: --select, --compact, --quiet, --plain, --agent) silently changes the *routing* to this branch but has no effect on the body. `export daily-returns --select date,row_key` returns full records and `--quiet` returns the entire dump. Bypassing printJSONFiltered is correct for this command (a streamed JSONL/CSV dump cannot be a single filtered JSON document), but the flags are accepted and silently ignored rather than rejected or honored; a usageErr for --select/--quiet on this command, or a line in Long saying they do not apply, would close it.
