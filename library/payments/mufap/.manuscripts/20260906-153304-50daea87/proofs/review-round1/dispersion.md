# Review findings for internal/cli/dispersion.go

[MAJOR] Silent payload-decode drops are misreported as market holidays. $HOME/printing-press/.runstate/personal-74f0f171/runs/20260906-153304-50daea87/working/mufap-pp-cli/internal/cli/dispersion.go:160-163 does `if err := json.Unmarshal(...); err != nil { continue }` with no counter and no stderr note. Two consequences: (a) a partial decode failure silently narrows the cross-section, so the emitted fund_count understates the universe and the reader cannot distinguish 'few funds reported' from 'rows did not decode' — exactly the failure the contract's 'failed fetches never counted as zeros / surface universe width' clause targets; (b) if every row for a date fails to decode, DeriveDispersion returns FundCount 0 and line 178-180 drops the date entirely, while the Long text at lines 61-63 explicitly trains the reader that an omitted date means 'MUFAP publishes nothing on weekends and holidays'. A mirror-format mismatch is therefore presented as a market absence. The sibling command already does this correctly: internal/cli/rates.go:133-140 counts `malformed` and warns at rates.go:157 (`warning: skipped %d mirrored row(s) whose payload did not decode`). Fix: count the failures and emit the same stderr warning (and count a date lost wholly to decode failure separately from a genuinely unreported date).

[MAJOR] Wrong human-detection predicate for the thin-cross-section warning. dispersion.go:188 branches on the package global `humanFriendly` (internal/cli/helpers.go:77, set only by the --human-friendly flag, root.go:308) to choose prose vs JSON, while stdout routing nine lines later at dispersion.go:197 correctly uses `wantsHumanTable(cmd.OutOrStdout(), flags)` (helpers.go:2491, which is `!machine && (humanFriendly || isTerminal(w))`). The two disagree on the most common paths: a plain interactive terminal run prints a human table on stdout but dumps the raw JSON event line from dispersion.go:192 onto stderr; conversely `--json --human-friendly` emits prose alongside machine stdout. Use `wantsHumanTable(cmd.OutOrStdout(), flags)` at line 188. Secondary defect in the same branch: line 192 hand-builds JSON with Printf and `%q` for the user-supplied category, which is Go-quoting, not JSON-quoting — a non-UTF-8 --category value yields `\xNN` escapes and invalid JSON. No sibling emits a JSON stderr event (rates.go:157/201/203, panel.go, coverage.go, universe.go all use plain prose), so a plain warning string is also the house-consistent fix.

[MINOR] `--category ""` silently disables category filtering and pools incompatible return conventions. dispersion.go validates --column exhaustively (lines 86-97) but never validates --category; it is passed straight through at line 174. internal/mufap/derive.go:114 filters only `if category != ""`, so an empty or whitespace --category matches every row: annualized money-market yields (10-20) pooled with absolute equity returns, producing a p90-p10 'spread' the mufap package itself calls meaningless (derive.go:60-64: 'Mixing the two in one median compares a yield with a price change'). rates.go guards this explicitly via IsAnnualizedCategory; dispersion has no equivalent. Related: DispersionPoint.Category (derive.go:101) echoes the user's raw substring, so the JSON never reveals which MUFAP category labels were actually pooled (e.g. --category 'Money Market' also sweeps in VPS- pension variants). Minimum fix: reject an empty/whitespace --category with usageErr in the same block as the --column check.

[MINOR] Duplicated return-column list, contrary to the contract's 'same return-column list rates uses'. dispersion.go:31-35 declares `dispersionReturnColumns` while internal/cli/rates.go:24-27 declares `ratesReturnColumns` with byte-identical contents. No behavioral difference today, but two sources of truth in one package for the same MUFAP header labels will drift the moment MUFAP adds or renames a period column, and the two commands would then accept different --column sets against the same 'daily-returns' resource. Promote one list (ideally into internal/mufap alongside the payload-key knowledge) and have both commands reference it.

[MINOR] No Args guard, so stray positionals are silently ignored and also suppress the help branch. dispersion.go:74-77 gates help on `len(args) == 0 && cmd.Flags().NFlag() == 0`, and the command sets no `Args:` field, which leaves cobra's default ArbitraryArgs. `mufap-pp-cli dispersion 2026-09-01` therefore neither prints help nor errors: the date argument is discarded and the command silently runs over the entire mirror with default --category/--column. Adding `Args: cobra.NoArgs` keeps the contract's ban on MinimumNArgs/MarkFlagRequired while turning a plausible agent mistake into a usage error instead of a wrong-window answer. Note this pattern is shared with rates.go:61, panel.go:73 and coverage.go:116, so fixing it here is a package-wide convention change rather than a dispersion-only bug.
