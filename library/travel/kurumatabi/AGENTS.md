# Kurumatabi CLI agent guide

This is a read-only printed CLI for the public RV Park / Kurumatabi ecosystem. Read `README.md` for evidence semantics and `SKILL.md` for agent routing. Use `kurumatabi-pp-cli parks --help`, `kurumatabi-pp-cli doctor --json` and `kurumatabi-pp-cli agent-context --json` for runtime truth.

Keep custom domain code in `internal/parks` and the preserved CLI extension files; use `registerNovelCommand` hooks for wiring. Keep the authored spec and research narrative in run evidence as the source for generated descriptions. Preserve fixtures and reviews when regenerating. Library automation assigns release versions and updates the registry and skill mirror after merge.

Source evidence wins over generic policy. Preserve stable IDs, Japanese names, canonical URLs, JST observation/publication dates, metre units, tariff audiences and conditional rules. Unknown facilities, fees, membership or dimensions remain unknown. Same-day reservations are not vacancy; overnight parking is not general camping permission. No CLI command books, pays, logs in or contacts a host.

Hand-written commands declare one `pp:data-source` strategy and matching MCP annotations. Auto mode prefers live with explicit cached fallback; local-only reads reject live mode. Share bounded context, adaptive source limiting, typed throttle errors and common output filtering. Keep array outputs initialized and preserve actual aggregation denominators/fetch failures. Resolve default cache paths after runtime home settings apply.

Tests must assert behavior and negative/unknown cases, including native session pagination, legacy icon state, explicit wastewater prohibitions, conditional fees, exact opening labels, cached fallback, fit, matrix comparison, distance ranking and service partitions. Run the smallest relevant tests during edits; the final gate is uncached tests, vet, build, complete shipcheck, real read-only dogfood and measured representative performance.

Use the generated local learning loop only for structural questions, with personal identifiers removed; deterministic checks use `--no-learn`. Keep secrets and session values out of code, docs, proofs and receipts. GitHub publication or bookings require a separate user instruction.
