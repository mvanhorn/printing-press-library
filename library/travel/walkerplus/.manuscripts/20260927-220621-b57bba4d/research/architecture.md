# Walkerplus implementation contract (proposed, pending scope approval)

## Product surface
`walkerplus-pp-cli search` is cheap listing-only discovery. `shortlist` enriches bounded candidates with detail/data/price and ranks trip matches. It returns only candidates actually enriched; candidates beyond max-details are omitted with explicit truncation metadata. `event ID|URL` returns one fully sourced event. `areas [--prefecture tokyo]` and `categories` expose accepted canonical codes/aliases/Japanese labels. JSON is default compact. --select/--fields projects requested event fields while retaining query and coverage metadata. No LLM/title translation dependency.

## Accuracy
Search matches ISO event envelopes, labels activity as possible/unverified, and never equates overlap_days with confirmed attendance days. Listing cards carry stable IDs and category/region links; JSON-LD Event array supplies dates/locality/official URL. Join by unique exact title/venue, with count/order consistency fallback only after verifying title equality; ambiguity leaves missing data rather than misassociation. JSON-LD url is ORGANIZER URL, not event ID. Keep entire source Japanese schedule and caveats.
Shortlist retrieves explicit schedule before evaluating known occurrence dates, closure weekdays, date exclusions and recurrence. Exact date arithmetic uses Asia/Tokyo calendar dates. Unsupported/holiday-dependent rules yield possible match and unresolved notes, not invented activity. Seasonal approximate phrases such as 上旬/見頃/予定 produce approximate certainty even when JSON-LD assigns artificial endpoints. Unknown or open-ended intervals remain unknown/possible. Current edition never rolls to next year. Native month/day routes have no year control: discover bounded relevant months when supported, record exact sampled route URLs and their native year labels, and state undisclosed future editions cannot be manufactured. A cross-year trip may legitimately yield incomplete/empty next-year results. Cancellation/postponement preserved separately; canceled events excluded from default trip recommendations with exclusion count. starts/ends refer to source envelope boundaries, clearly labeled.
Free requires event admission evidence (not parking/children/free subarea). Paid/unknown/mixed distinguishable; numeric price may stay null alongside text. Indoor true requires unconditional explicit indoor-venue/indoor-event phrase; indoor-on-rain or mixed indoor/outdoor remains unknown. reservation_required comes only from explicit reservation facts, never schema offers.InStock.

## Boundedness and provenance
Default limit10, max-pages3, start-page1; hard caps limit100,max-pages20; shortlist max-details10 default/hard cap30; concurrency2 hard cap4; retries2 hard cap3. Timeout15s per request and overall context bound; response body <=4MiB. Retry only429/5xx/transient, honor bounded Retry-After, no infinite retry. Stable dedup by Walkerplus ID (edition year remains explicit); tie sort ID ascending. Default shortlist sort: confirmed then possible, earliest matching/source start, source end, ID. sort start/end/source alternatives with reason fields. Results always bounded, coverage exposes requested/scanned pages, candidate/detail counts, truncated/reasons,next-page,source_total if supplied,cache hits,request count,elapsed_ms. Source HTTP errors or parser shape drift never masquerade as empty results. Partial fetch failure either nonzero JSON error or explicit incomplete coverage; choose documented consistent contract.
Cache source HTML only under standard user cache or explicit --cache-dir; bounded count/bytes with TTL default1h and --refresh; --no-cache optional. Each event freshness records fetched_at/cache age; source published updated text separately, never conflate. Existing shared config untouched.

## Ownership plan
Core agent owns internal/walkerplus domain types, HTTP/cache, catalogs, listing/detail parser, schedule logic, matching/ranking and core tests. CLI agent owns command surface/output/flags, main.go, go.mod integration, README/SKILL, CLI tests and live E2E/measurement harness. Orchestrator authors source spec/research/acceptance, runs workflow tools and reviews. Single shared contract file core owns types; CLI calls exported client methods.

## Acceptance
Deterministic tests: exact/multi-day/weekly recurrence+exclusions, impossible dates/leap and year boundary, holiday exception unresolved, approximate season vs confirmed, zero-results []/unknown null, paid price None, free-parking false positive, mixed/conditional indoor, duplicates and stable order, invalid URLs/location/field selection, cache/retry/request limits.
Live: independent prefecture/category/date combinations across Tokyo, Kyoto/Osaka, Hokkaido and a regional prefecture; assert each returned location/code and year-aware envelope intersects query, no duplicates, shortlist date confidence honors exceptions. Explicit known detail cases include ar0313e603640 reservation-required paid exhibit; ar0101e66092 rainy/strong-wind caveat; ar0727e612159 unconditional indoor. Fetch source fresh at test time; E2E tests gated env flag. Performance proof captures stdout bytes, request count, elapsed and /usr/bin/time -l peak RSS for representative search, enriched shortlist, single detail; cache cold/warm separately. Build/test/vet and shipcheck pass, no public publish.

## City resolution refinement (root review)
Known aliases reuse embedded verified routes. A non-built-in source city code, or alias/Japanese name with an explicit prefecture, resolves through at most one current prefecture navigation lookup. That catalog lookup is separately counted from event listing pages; total HTTP attempts include it. Exact source city path and label govern routing/locality checks. A missing catalog city is a usage error; fetch failure remains a source error. No slug guessing or silent empty result.
