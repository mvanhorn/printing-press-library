# JMA research and agreed scope

Verified 2026-10-01 JST, free anonymous HTTPS, no account, credential or purchase. Only JMA hosts at runtime. The supplied [forecast services](https://www.jma.go.jp/jma/en/Activities/forecast.html) explains short and weekly forecasts and typhoon analysis. [Terms](https://www.jma.go.jp/jma/en/copyright.html) require attribution for reuse; transformed data is identified as such. Public website JSON is a replayable first-party frontend contract, not a versioned guaranteed API. No published numeric rate limit found; client self-limits sequential requests and one retry.

## Source contract and coverage

- `common/const/area.json`: offices, class10 forecast districts, class15 subdivisions, class20 municipalities; source Japanese/English names and parent-child IDs.
- `forecast/const/forecast_area.json`, `week_area.json`, `week_area_name.json`, `en_amedas.json`: short district / weekly region / temperature station relationships. No geocoder. Municipality resolution walks source parents; stations are forecast reference stations, not observations.
- `forecast/data/forecast/{office}.json`: short and weekly `timeSeries`, parallel `timeDefines` / values, precipitation probability (%), station temperatures (°C), Japanese winds and waves, confidence A/B/C and temperature ranges. `014030` maps to `014100`, `460040` to `460100`, as first-party Forecast.Common.getPathCode defines. Precipitation slots are six hours; weather days run to JST midnight, weekly days midnight to midnight. Short `temps` indices depend on issue hour: source frontend inspected; output retains each source time and type, with explicit period interpretation.
- **Current warnings use `warning/data/r8/{office}.json`, an array of product bulletins**, not legacy `warning/data/warning/{office}.json`. Legacy returned HTTP 200 but was frozen at 2026-05-28. The current source frontend uses r8 and the new urgent warnings/landslide classification. Each product has separate report time, source code, status and municipality kinds/properties. Never merge product-level no-warning claims into global clearance. Excludes joint river flood bulletins and coastal forecast-zone additions; label coverage partial for those hazards. Never infer all-clear from absent records, unknown status/code, stale HTTP cache, missing product/municipality or failed retrieval. Keep issued / continued / updated (downgrade) / lifted distinct, no fabricated lifecycle history.
- `typhoon/data/targetTc.json`: current `tropicalCyclone` IDs (including developing depressions), issue time and category; list stays lazy.
- `typhoon/data/{TCid}/forecast.json` and `specifications.json`: title issue/name; analysis/estimate/forecast parts and validtimes; geometry centers `[lat,lon]`, geometry radius metres, specifications radius km/nm, pressure hPa, sustained/gust m/s and knots, movement km/h and knots. Join by validtime, require coherent issued times or fail incomplete. Historical analysis track lacks individual times; only emit on detail request and label untimed analysis, never forecast. Forecast centers are uncertain, not promised paths.
- [Typhoon explanation](https://www.jma.go.jp/jma/kishou/know/typhoon/7-1.html): probability circles express uncertainty of the cyclone center, 70% probability at the specified forecast time, not storm size. Center lines are not necessarily the route. Storm warning area is conditional on the center being inside its forecast circle; outside-circle locations can still experience hazards.
- [Warning explanation](https://www.jma.go.jp/jma/kishou/know/bosai/warning.html): 2026 classification, source Japanese names include alert level for rain, landslide and surge; urgent warning is JMA's English term. Municipality warnings do not replace evacuation instructions.

## Workflows and pain points

Resolve an unambiguous source ID before fetching; inspect a destination's short/weekly forecast without temperature stations leaking from other districts; inspect warning source lifecycle and retrieval completeness; discover active typhoons before lazy coherent detail; refresh inventory explicitly. Pain points: old endpoints return plausible stale data; prefecture-level raw output hides municipality specificity; forecast and analysis paths are easily confused; missing strings must remain null.

## Ecosystem

`eggplants/jma-api-doc` is archived (2021); endpoint examples only, not current authority. `kakarsatoshi-bot/japan-weather-mcp` exposes today/week/cities/ping. `koizumikento/jma-data-mcp` offers forecast, station listing/search, current/history observations and nearby lookup; observations/history/geolocation are outside this focused forecast scope. Package searches found a 2015 PyPI jma downloader and weather wrappers, no official supported SDK/OpenAPI. Research corroborates scope only; runtime integrates no third party. Source correctness comes from JMA's actual frontend and fresh JSON. Public registry had no same-provider match. Shared global configuration and skills were left unchanged by explicit user instruction; no installs or global updater. Sole builder, exactly one fresh independent reviewer replaces the skill's additional ideation/review workers per explicit user instruction.

## Product / agreed decisions

Go CLI `jma-pp-cli` (also buildable as `jma-cli`), compact JSON by default with metadata preserved under projection. Bounded local catalog search/pagination, lazy short/week forecast and warning detail, typhoon list/get, inventory refresh, offline inventory, doctor and cache refresh/bypass. HTTP cache TTL forecast 5 minutes, warnings/typhoons 60 seconds; no stale fallback. Source issue age shown without conflating long-lived warning issue age with expired warnings. No authoritative validity end assumed for warnings. No safety scoring, booking, publishing, long-range forecasts, radar, earthquake/tsunami/volcano or observations. All approved functionality must be shipped; no stubs.
