What the peer-review gate fixed before publish

  • Unshimmed rename of the flagship command → hidden deprecated alias + upgrade docs
  • Generated local list loaded the whole store (7 s / 3.9 GB at 300k rows) → bounded SQL push-down; legacy/partial stores fall back with a hint
  • reach full-scanned per destination → expression indexes (0.56 s → 4 ms)
  • availability_all preferred stale rows over fresher cached-search copies → freshest-wins by synced_at
  • immutable=1 reads on a rollback-journal store (torn reads reproduced) → mode=ro
  • Dead route_id indexes (generator never matches RouteID) → real indexes; first-seen + source indexes
  • Backfill + view rebuild on every open (+0.57 s per command) → one-time, gated
  • search <query> POSTed a fabricated body to the metered /live endpoint → local-only
  • Auto-refresh issued a guaranteed-400 API call per read after the stale window → honest skip
  • doctor migrated the store as a side effect → read-only + migration_pending
  • MCP intents annotated destructive → read-only/non-destructive; honest descriptions
  • Novel commands: silent-empty on never-synced stores, no usage envelope → meta.synced, {error,usage}, exit 3 on all-failed refresh, per-item reach degrade, empty-CSV header rows
