# JAPAN47GO CLI brief

## Source and thesis
JAPAN47GO public Japanese tourism records carry local guide-association request conditions that change whether an itinerary can proceed. Runtime uses anonymous standard HTTPS SSR pages at https://www.japan47go.travel/ja/search/result and /ja/detail/{UUID}. No browser, API key, booking, payment or messages. The completed ten-question assessment spans Hokkaido, Nagano and Fukuoka; ten HTTP200 details and repeated homepage/Nagano area pages passed. Saved source evidence remains private. The browser keyword page raised a client-render error but the public SSR response works.

## Users and workflows
Independent travelers need to discover guide candidates, inspect published terms before requesting a date, compare a small shortlist against notice/party/fee requirements, and revisit normalized observations offline. Four commands implement five behaviors: services discover; services inspect; services compare notice/party constraints; services compare qualified fee evidence; services saved. No generic event recommendation engine. Exact date facts can be inspected but never imply daily operation.

## Existing-tool decision
Shared shipped skill contracts and actual bounded Walkerplus/Japan Guide/Asoview/Iko-yo probes were inspected. Japan Guide provides English editorial destination facts; Walkerplus provides edition-aware events; Activity Japan already checks JA/EN indexed coverage; NAVITIME already provides passes. None of those inspected contracts supplies the Tsumago ten-day request/four durations, Hakata one-week deadline/expense categories, or Tanushimaru two-person minimum/ten-day rule. Empty bounded scans are not absence evidence. A focused new source CLI preserves the Japanese municipal/association authority rather than extending the editorial Japan Guide contract.

## Observed contract
__NEXT_DATA__ props.pageProps: search has searchQuery/items/pageInfo; detail has article.data. Search tags: guides62, experiences69, events5; detail guide category617 is not search62. Query keyword is supported; pageInfo.totalCnt is matching count while top-level totalCount is global and excluded. Page size20, pageNo/totalPageCnt permit bounded continuation. Query parameter page is verified during runtime development. Listing output excludes thumbnails, contact/profile/staffing/guide-age fields. Detail output includes only curated normalized decision facts and bounded Japanese originals.

## Data and limits
Store at most200 normalized service observations with fetch timestamps, at most64KiB each, normal SQLite transactions; read-only saved commands do not create storage. Discovery default1/hard5 pages and default10/hard50 outputs, never completeness claims beyond those pages. Compare2-5 UUIDs; detail cache freshness explicit. Successful detail inspections save local normalized facts. Missing/no-cache errors are distinct from HTTP unavailable, parser failure, unknown availability, publisher-marked closed and unsupported types.

## Meaning and safeguards
closed=false is not open_now. Multiple notice rules stay ambiguous. Old winter hiatus and source dates do not extrapolate. Office closing text remains office evidence, not tour closure. Expense-based volunteer services are not free. Numeric fees need qualifiers and units; unknown totals remain null. Compare checks only published rule compatibility, never availability. Preserve separate source_updated_at and observed_at. No raw payload exports or personal contacts. Tests cover arithmetic/month boundaries, multiple deadlines, archived hiatus, price units, privacy and bounded coverage. CLI/MCP calls must agree.

## Approved implementation
Four commands and five small behaviorful feature rows were explicitly authorized by the detailed user briefing; scope/feature and publication menus are resolved. Exactly one root-assigned fresh reviewer owns phases14-17. No nested generation agents or updaters.
