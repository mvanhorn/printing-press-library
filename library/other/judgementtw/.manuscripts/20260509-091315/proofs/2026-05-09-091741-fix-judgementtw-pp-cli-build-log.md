## Architecture decisions worth recording

- **No dependency on `client.Client`'s generic JSON pipeline** for content commands. The generator's `client.Client` is JSON-API-shaped; HTML scraping needed dedicated source packages with cookie jars and form-encoded POST. The two source packages are deliberately small (~150 LOC each) and use only stdlib `net/http` + the shared `cliutil.AdaptiveLimiter`.
- **Per-source rate limiting** via `cliutil.AdaptiveLimiter` is wired into both `fjud.Client` and `fjudkm.Client` per the AGENTS.md per-source rule. 429 → `*cliutil.RateLimitError` so empty-on-throttle is impossible.
- **Citation-extraction false-positive cleanup**: initial bare-statute fallback regex matched common phrases like "違法", "依法", "於法" producing 22 garbage rows on a single judgment. Removed the fallback; statutes are only indexed when an article number is present (e.g., `刑法第50條`). Verified clean: 4-judgment corpus produces 2 article-form citations and zero noise.
- **Privacy-purge auto-delete on `查無資料`** is wired into both `judgments get` and `purge orphans`. Both write to `change_log` for audit trail. Required by Judicial Yuan ToS.
- **Mid-build problem and resolution**: ASP.NET WebForms metadata parsing initially used a single non-greedy regex over the int-table block, but nested divs caused it to truncate. Replaced with per-label regex (`裁判字號\s*[：:]?\s*</[^>]+>\s*<[^>]+>\s*([^<]+)`) targeting the `<td>label</td><td>value</td>` template the site uses. Body extraction switched from regex-match-block to slice-between-anchors (start of `htmlcontent` div → first `copy-url`/`law-tool-box` sibling).

## What was intentionally deferred

- **`sync` command**: kept the generator's emitted body. It tries to GET the JSON endpoints in the spec (which don't exist as JSON) and reports failures. Fixing this requires a 200-line custom override that paginates `find` by court + year and bulk-stores results. **Practical workaround**: the user can call `find --json | jq -r '.items[].jid' | xargs -I {} judgmenttw-pp-cli judgments get {}` to populate the store. The novel features all work as soon as judgments are present.
- **CJK FTS5 tokenizer wiring**: the generator's `store.Search` uses default FTS5; Chinese text gets indexed but search relevance is character-level, not word-level. Acceptable for v0.1; a trigram tokenizer would improve recall for partial-match queries.
- **Constitutional Court (cons.judicial.gov.tw)**: not yet implemented as a third source. Constitutional rulings are accessible via `find --type constitutional --court JCC` since FJUD includes the Constitutional Court (JCC) in its 41-court list.
- **Official open-data API path**: explicitly skipped per Phase 1.6 user choice. The CLI defaults to website scraping (24/7); operators wanting the bulk JList/JDoc API path can add it later as `internal/source/opendata/`.
