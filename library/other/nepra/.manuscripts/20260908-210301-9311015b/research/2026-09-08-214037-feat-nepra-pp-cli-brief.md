## Reachability Risk
- **None/Low for S1 and S2.** Evidence: 3× S1 files fetched then re-fetched **byte-identical md5** (2017-18 `f6a63e4b…`, 2020-21 `722f4893…`, 2023-24 `044cc6ca…`), no retries needed, plain `curl --max-time 30` with a browser UA [P2]; independently, seven years' byte counts reproduced **exactly** against a prior brief [P1]. **[mine, today]** two S2 tariff pages returned 200 at their exact recorded byte counts on first attempt. No Cloudflare challenge, no rate-limit, no session/CSRF handshake anywhere on S1/S2.
- **High for everything else:** Power BI backend (403 / empty reply) [P1]; `ntdc.gov.pk` → **HTTP 000, 0 bytes on 3 attempts** [P1]; `data.gov.pk` → 404 [P1]; **both sitemaps declared in robots.txt are dead — `sitemap_1.xml` and `sitemap_2.xml` → HTTP 404, 9-byte body "Not Found" [mine, today]**; PIDE/SDPI/IEEFA/Business Recorder blocked (403/Incapsula) [P1].
- **Governance — robots.txt fetched today: HTTP 200, 1,944 B, `text/plain` [mine, today].** Verbatim generic block: `User-agent: *` / `Content-Signal: search=yes,ai-train=no,use=reference` / `Allow: /`, and a second later `User-agent: * / Allow: /`. Inside a `# BEGIN Cloudflare Managed content` block, `Disallow: /` for: **Amazonbot, Applebot-Extended, Bytespider, CCBot, ClaudeBot, CloudflareBrowserRenderingCrawler, Google-Extended, GPTBot, meta-externalagent**. No `Crawl-delay`. **What it permits:** a generic, non-listed user agent is explicitly allowed the whole site — a user-invoked CLI is in scope of `Allow: /`. **What it forbids, and the build must encode:** (1) never send a UA matching any listed crawler — ship a distinct product UA (e.g. `nepra-cli/<ver> (+repo URL)`); (2) `ai-train=no` — the README and any published dataset must state the data is **not** for model training; `use=reference` supports citation-with-provenance, which is exactly our product; (3) the site is Cloudflare-fronted, so treat a JS-challenge response as a hard stop, not something to defeat; (4) sitemaps are dead, so **enumeration cannot be sitemap-driven**.

## Top Workflows
1. **`nepra gen --year 2023-24 --format csv|json|tsv` — plant-level generation extract.** Local data: the 7 cached `sheet001.htm` bodies (418–517 KB) decoded cp1252 → 108/108/133 plant rows × 32 columns with `%age` and `GWh` per month plus Sum. Nobody in the ecosystem can do this today [P1].
2. **`nepra plant "Tarbela" --history` — cross-year plant series.** Local data: the 7-year store plus a **plant alias table**, required because S.No is not stable across years (2017-18 row 1 = `AES Lalpir power limited.` / THERMAL; 2023-24 row 1 = `Tarbela Hydropower Project (WAPDA)` / HYDEL) and names drift (`Narowal Energy Ltd. (HUBCO)` → `Narowal Energy Ltd.`) **[mine, today]**.
3. **`nepra agg --by technology|fuel --year …` — fleet/utilisation rollups.** Local data: normalized `technology`/`fuel` enums + `installed_capacity_mw`/`dependable_capacity_mw` + monthly GWh. Enables plant-count and capacity-mix deltas (thermal 42→32 rows, wind 20→36, solar 4→8, coal 4→8 between 2017-18 and 2023-24) that today only exist inside Tableau embeds [P1].
4. **`nepra verify [--crosscheck iea]` — provenance and reconciliation gate.** Local data: per-file `url, http_status, bytes, md5, fetched_at, header_fy_token`, plus the IEA JSON cache (204 rows, 1990–2023). Asserts the workbook's own header FY token matches the requested year, byte floor, and 1 table / expected `<tr>`,`<td>` counts; exits non-zero when stale. Sum-of-Sum for FY2023-24 is **126,166.8 GWh** against PECI's headline **137 TWh** for FY24 [P1] — a ~10.8 TWh gap the tool should surface, not hide (cause **UNVERIFIED**).
5. **`nepra tariff --disco LESCO` — DISCO tariff tables.** Local data: 11 cached `/tariff/Distribution%20<DISCO>.php` bodies (79,652–349,772 B, UTF-8, 2–21 tables each) **[mine, today]**. This is the honest tariff path; the SRO PDFs are not (see Traps).
6. **`nepra export --dataset gen --release` — a citable, versioned dataset** for MapYourGrid/gridinspector/academic use. Local data: the whole store plus a manifest of source URLs and md5s. Bangladesh's 1,867-daily-report ScienceDirect dataset is the proven template [P1].

## Table Stakes
From the ecosystem probe — any credible tool must have all of these, and every one already exists somewhere in the ecosystem, so their absence is a visible deficiency:
- **Per-row provenance objects.** `ebillpakistan.pk` ships `NEPRA_SOURCE {name, url, htmlMirror, notifiedOn, effectiveFrom, supersedes}`, `SRO_BY_DISCO` (11 DISCOs), `CATEGORY_SOURCE` with a `stillInForce` pointer [P1]. Match it.

- **Refusal over interpolation.** `bijlicheck` explicitly refuses K-Electric, Time-of-Use, and readings it can't reconcile [P1]. Our equivalent: never interpolate a missing year, never synthesise a plant row, emit `UNAVAILABLE` and a non-zero exit.
- **Degraded/offline operation.** `bijlicheck` runs fully on seed data with no API key and no DB; `ha_wapda_peak_hours` is "100% offline" [P1]. The CLI must serve every query from the local cache with no network.
- **Reproducibility as a claim.** Re-fetch md5 equality [P2] is the evidence; publish the md5 manifest.
- **A real license.** `bijlicheck` and `ebillpakistan.pk` have **none**; `nepradataset` has none; `ha_wapda_peak_hours` is MIT [P1]. Ship an explicit license for code and a separate, stated position on the data (see robots.txt `ai-train=no`).
- **Distribution + name claim.** PyPI 0 packages, npm 0 packages, 0 MCP servers for Pakistani energy — while Nigeria already has `@braynexservices/nigeria-mcp-electricity` [P1].

## Data Layer
- **Primary entities:**
  - `source_file` — `surface, url, fy_token, http_status, bytes, md5, content_type, declared_charset, fetched_at, header_fy_token` (the last is the workbook's own `FY 2023-24` string, the anti-decoy anchor).
  - `plant` — `plant_key` (normalized name), `display_name`, `technology_raw`, `technology_norm`, `fuel_raw`, `fuel_norm`, plus an `plant_alias(plant_key, alias, first_fy, last_fy)` table. **Do not use S.No as an identity** — ordering is re-sorted between years **[mine, today]**.
  - `plant_fy` — `plant_key, fy, s_no, installed_capacity_mw, dependable_capacity_mw, status_note` (`DELICENSED`, `Export to K.Electric`, or NULL), `row_arity`, `row_class` (`full|no_data|annotated|delicensed`).
  - `plant_month` — `plant_key, fy, month (Jul..Jun|Sum), utilisation_pct, energy_gwh, is_null` — 13 rows per plant-year; **null ≠ 0**.
  - `tariff_page` / `tariff_row` — DISCO, table index, verbatim cells, `w.e.f` where present, source URL, md5.
  - `document` — SIR/PER/SRO PDFs with `year, bytes, md5, has_text_layer` (`sir2023.pdf` → `has_text_layer=false` **[mine, today]**).
  - `crosscheck_iea` — the 204-row JSON cached verbatim.
- **Sync cursor:** **the fiscal-year token, not a timestamp.** Cursor = `max(fy)` present, advanced by *probing constructed URLs* across a candidate range; 2015-16, 2016-17, 2024-25, 2025-26 currently 404/9 B [P1]. Change detection is content-addressed: `(bytes, md5)` per source file — an unchanged md5 is a no-op, a changed md5 on an existing FY is a **revision event** that must be recorded (not overwritten), because the SIR is publicly disputed and revisable [P1]. For S2 tariff pages the cursor is `fetched_at` + md5 (no version token exists).
- **FTS/search:** SQLite FTS5 over `plant.display_name`, aliases, `technology_raw`, `fuel_raw`, and PDF text. Indexing **must** normalize first: `0xA0` → space, collapse runs of whitespace (source names contain wrap artifacts, e.g. `Mangla Hydropower   Project (WAPDA)`), unescape entities (`&amp;` appears in the table title), casefold. Fuzzy/trigram matching is mandatory, not optional: upstream typos are in the URLs and filenames themselves (`Genenration`, `Industerial`) [P1] and plant names are renamed between years **[mine, today]**.
- **Schema-stability constraint — yes, the upstream schema drifts, in four measurable ways [mine, today unless noted]:** (1) **row count** 114 → 139 `<tr>`, 108 → 133 plants; (2) **colspan attribute count doubles**, 15 → 30 [P2]; (3) **row-shape classes change identity per year** — arity 4 "listed but no data" rows in 2017-18 (11 of them, e.g. `Karachi Nuclear Power Plant-II (K-2)`), arity 5 `Export to K.Electric` annotations in 2020-21 (3), arity 6–7 `DELICENSED` rows in 2023-24 (15); (4) **enum vocabulary drifts** (`Coal` present 2017-18/2020-21, absent 2023-24; `HYDEL` as a *technology* appears only in 2023-24). What the store does about it: keep **raw bytes immutable and content-addressed**; hold a **versioned per-FY column map** derived from the colspan/rowspan-expanded header band and keyed by the workbook's own `FY` token; **validate every row against the technology enum** and, on failure, re-anchor rather than trust position; classify each row into `row_class` and persist `row_arity`; and if a year's header band does not match a known map, **refuse to emit rows for that year** (`UNAVAILABLE`, non-zero exit) instead of emitting mis-aligned columns.

## Product Thesis
- **Name:** `nepra` — Go CLI, binary `nepra`, with an MCP server shipped from the same binary. The name is free everywhere: `registry.npmjs.org/nepra` → 404, and "nepra" never appears as a package name in PyPI's full 45,845,070-byte simple index; no MCP server exists for Pakistani energy [P1]. Claim `nepra` on npm as a thin installer wrapper early.
- **Why it should exist:** NEPRA has published **seven fiscal years of machine-parseable Excel-exported HTML** — FY2023-24 alone is 1 table, 139 rows, 4,965 cells, 133 plants × 32 columns — and **nobody has parsed it**, because the files are windows-1252 and a naive UTF-8 read returns `<table>=0, <tr>=0, <td>=0` and the file **looks empty**; the single offending byte is `0xA0` (128 occurrences in FY17-18/FY20-21, 132 in FY23-24; first at offset 7076) [P1, P2]. Meanwhile: PyPI 0, npm 0, HDX 0, energydata.info 0, Open Data Pakistan 0, Kaggle 2 undocumented dumps (usability 0.25 and 0.0), `data.gov.pk` 404; a GitHub repo literally named `nepradataset` is 10–14 hand-typed spreadsheet rows plus a PDF, saved from desktop Excel (`printerSettings1.bin` inside); the best-funded incumbent (Renewables First / PECI) ships a 50-page InDesign PDF footered "Data Source: NEPRA State of Industry Report" on every page with Tableau embeds and **no API, no export** (`/api` → 404, zero `.csv`/`.json`/`download` strings in its HTML); and the incumbent wrote our thesis themselves: *"Critical data… sits scattered across different agencies, often outdated or inaccessible… This data vacuum perpetuates poor decision-making"* [P1]. The moat is a one-line encoding fix the entire ecosystem walked past — and because the regulator's own minister calls the report "incomplete and inaccurate" and five months late [P1], **provenance and vintage are correctness features, not polish**.

## Traps
Each with the assertion that neutralises it.
1. **Encoding (load-bearing).** windows-1252; naive UTF-8 read yields 0 tables/rows/cells and the file looks empty. Sole offending byte `0xA0` (128/128/132 occurrences; first at offset 7076 inside `<span style='mso-spacerun:yes'>`); `iconv -f UTF-8 -t UTF-8` fails on all three files [P1, P2]. → Read bytes, decode cp1252 explicitly, and assert non-zero tag counts after decode.
2. **FY path token has no `FY` prefix.** `…wise%20FY2021-22_files/…` → 404/9 B; `…wise%202021-22_files/…` → 200/516,219 B [P1]. → Construct with the bare `YYYY-YY` token.
3. **Upstream typos are load-bearing.** `Genenration` in the URL; `Industerial` in the ecosystem dataset [P1]. → Preserve verbatim; never "correct" a path.
4. **Silent 404s.** 9-byte `Not Found` body served as `charset=iso-8859-1`, HTTP 404 [P1; re-confirmed today on both sitemaps]. → Assert status **and** a minimum byte floor (~400 KB for S1).
5. **Frameset decoy.** The obvious per-year `…wise%202023-24.htm` returns **200** but is 9,838 B and byte-identical across 2017-18/2020-21/2023-24 — a `<frameset rows="*,18">` shell [P1]. → Only `_files/sheet001.htm` is data; treat a ~9.8 KB 200 as a failure.
6. **No directory index.** `/Detail%20of%20Generation/` → 403 [P1]. → URL construction + `filelist.xml`.
7. **Declared sitemaps are dead.** robots.txt names `sitemap_1.xml` and `sitemap_2.xml`; both 404 with 9-byte bodies **[mine, today]**. → Never make discovery sitemap-dependent.
8. **NEPRA's own index pages lie.** `Detail Report 2024.php` has 0 `<table>`/`<tr>`/`<td>` and links the **2022 and 2023** SIR PDFs [P1]. → Never trust an index as an enumerator.
9. **Zero `<th>` in every year.** Headers are ordinary `<td>`s identified only by position **[mine, today]**. → Positional map derived from the expanded 3-row header band; no `<th>` selectors.
10. **3-row header band with rowspan/colspan.** 6 rowspan attrs every year, colspan 15 → 30 between 2017-18 and 2023-24 [P2, mine]. → Expand the grid before mapping; a flat cell walk mis-assigns columns.
11. **Spacer cells.** 39–40 raw `<td>` per data row against 32 logical values **[mine, today]**. → Project to non-empty *after* grid expansion, and validate.
12. **A literal `;` junk cell.** Exactly one row per file (S.No 5 — `Atlas Power Ltd (APL)` in 2017-18/2020-21, `Warsak Hydropower Project (WAPDA)` in 2023-24) carries a 33rd cell containing only `;` **[mine, today]**. → Drop lone-punctuation cells; do not let arity 33 shift the column map.
13. **Ragged rows are semantics, not noise.** arity 4 = listed-with-no-data (11 rows in 2017-18, incl. `Karachi Nuclear Power Plant-II (K-2)`); arity 5 = `Export to K.Electric` annotation (3 rows in 2020-21); arity 6–7 = `DELICENSED` with capacity but no energy (15 rows in 2023-24, e.g. `Kotri Power Station`, `Thermal Power Station Guddu 1-4`) **[mine, today]**. → Classify and persist; emit NULL, never 0.
14. **S.No is not an identity.** Row ordering is re-sorted between years (thermal-first in 2017-18, hydel-first in 2023-24) **[mine, today]**. → Key on normalized name; keep S.No as an attribute only.
15. **Plant names drift and wrap.** `Narowal Energy Ltd. (HUBCO)` → `Narowal Energy Ltd.`; internal multi-space wrap artifacts (`Mangla Hydropower   Project (WAPDA)`); entity escapes (`&amp;`) **[mine, today]**. One earlier extractor rendered a wrapped name as two cells (`Tarbela` / `Ext. 04 Hydropower Project (WAPDA)` in `fy2324.tsv`), which the raw HTML does **not** support — that split is an extractor artifact, but it shows how easily this becomes a real bug. → Normalize whitespace + unescape before keying; maintain aliases.
16. **Enum vocabulary is inconsistent within a single year.** `THERMAL- COAL` (space after hyphen) alongside `Coal`; `GAS` / `Natural Gas` / `Natural Gas/ Furnace Oil`; `COAL` / `Lignite Coal` **[mine, today]**. → Keep `*_raw` verbatim and a curated `*_norm` mapping table; fail loudly on an unseen value rather than bucketing it.
17. **Number formatting.** Thousands separators throughout (`3,478`, `1,248.11`) **[mine, today]**. → Strip separators; never `parseFloat` a raw cell.
18. **Single-sheet workbooks.** `sheet002.htm`/`sheet003.htm` → 404; `tabstrip.htm` confirms one tab [P1]. → Don't assume multi-sheet, but do read both manifests — they're the only machine-readable metadata NEPRA ships.
19. **Per-character kerning in Pakistani government PDFs.** `National Electric Power Regulatory Authority` extracts as `N a ti o n a l  El e c tri c …`; exact grep → 0 hits, whitespace-stripped → 3; `not available` → 0 naive, 20 stripped [P1]. → Normalize before any PDF match; never report "not found" from a naive grep.
20. **Some SIR PDFs have no text layer at all.** `sir2023.pdf` (3,425,763 B) yielded a **0-byte** text extraction **[mine, today]**. → Detect and record `has_text_layer`; refuse rather than emit empty.
21. **"NEPRA data" claims are frequently false.** `jotilohana21/PowerCast` advertises "30+ years of NEPRA data"; its own README says the source is Our World in Data via Kaggle and the repo contains **zero** data files [P1]. → Verify any claimed NEPRA source against actual files.
22. **Registry name collisions.** PyPI `kelectric` = Spanish copper-conductor sizing lib; `mepcocalc` = "mini testing calculator"; `pypep-pepco` = Iranian payment SDK [P1]. → Read summaries, never match on name.
23. **GitHub search pollution.** Bare `nepra` returns ~90 Slavic-stem results (`nepravda`, `Neprazol`); use `nepra pakistan` (7 results) or code-search `nepra.org.pk` [P1].
24. **The SIR is not authoritative even to its own government.** The Federal Minister called it "incomplete and inaccurate", five months late, with "meter reading and billing… insufficient" data [P1]. → Every emitted row carries publication date and revision status; never present SIR figures as ground truth.
25. **DISCO own-site mirrors are stale.** LESCO's own tariff page's latest entry was "W.E.F 26-07-2023", three years stale, and was rejected as a source by a developer who checked [P1]. Note this is *lesco.com.pk*, **not** NEPRA's `/tariff/Distribution LESCO.php`, which is live and dense (21 tables, 305,982 B) **[mine, today]** — do not conflate the two. → Prefer NEPRA-hosted; verify per-DISCO freshness individually.
26. **Robots/UA trap.** `ClaudeBot`, `GPTBot`, `CCBot`, `Google-Extended`, `Amazonbot`, `Applebot-Extended`, `Bytespider`, `CloudflareBrowserRenderingCrawler`, `meta-externalagent` are all `Disallow: /` **[mine, today]**. → A borrowed AI-crawler UA turns a permitted fetch into a disallowed one. Ship our own UA; state `ai-train=no` compliance.
