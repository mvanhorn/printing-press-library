## Findings

### 1. Live dogfood marks a non-zero-exit happy path as `pass` rather than `skip` (Scorer bug)
- **What happened:** The gate recorded `verdict: PASS, 92/92, 0 failed` while six of those
  92 "passed" entries carried non-zero exit codes: `verify` happy_path and json_fidelity at
  exit 5, `basket` at exit 3, `weights` at exit 3. The commands were behaving correctly —
  they were reporting "I have no data" against a clean-room panel — but the harness labelled
  that `pass` instead of `skip`.
- **Scorer correct?** No. The command's own exit code is recorded in the artifact and
  contradicts the status beside it. `skip` already exists in the vocabulary and is used 65
  times in the same run for unmet preconditions; this is the same condition.
- **Root cause:** Verify/dogfood/scorecard. The happy-path evaluator treats a documented
  typed exit code as success. `pbs-pp-cli` declares `pp:typed-exit-codes: "0,5"`, and the
  affected commands exit 3 or 5 when the local panel is empty.
- **Cross-API check:** Yes, measured directly from committed gate artifacts:

  | CLI | tests in gate | happy_path/json_fidelity marked pass with non-zero exit |
  |---|---|---|
  | amazon-jobs | 126 | 8 — `teach`, `teach-pattern`, `teach-playbook`, `playbook amend`, all exit 2 |
  | cdc-pakistan | 189 | 4 — `coverage map`, `stats history`, both exit 4 |
  | nccpl | 326 | 2 — `contract-check`, exit 4 |
  | pbs | 157 | 6 — as above (0 after this session's CLI fix) |
  | psx | 333 | 0 (control) |
  | peekaboo | 166 | 0 (control) |

- **Frequency:** subclass — any CLI whose commands need local state a clean-room gate has not
  built. Three named APIs plus PBS, with two clean controls proving it is not universal.
- **Fallback if the Printing Press doesn't fix it:** Very poor, and this run is the proof. The
  mislabelling survived THREE consecutive full-live-dogfood runs on PBS and was caught by an
  external reviewer, not by the machine. It concealed a real defect in which 99 of 148 weekly
  releases were recorded complete while holding no weight vector, no weight totals and no
  quintile indices. A green 92/92 was the reason nobody looked.
- **Worth a Printing Press fix?** Yes. This is the shipping gate reporting success for a
  command that exited non-zero, and the acceptance marker it writes is the artifact that
  gates `publish package`. A gate that cannot distinguish "worked" from "declined for lack of
  data" cannot be used as evidence, which is its only purpose.
- **Inherent or fixable:** Fixable. The exit code is already captured.
- **Durable fix:** In the happy-path evaluator, treat a non-zero exit as `skip` with a reason
  (`"exited N: precondition not met"`), never `pass`. `error_path` legs keep their current
  semantics, where a non-zero exit IS the expected outcome — six such entries in this same PBS
  run are correctly `pass`. Then have `--write-acceptance` record `tests_passed` net of those
  skips so the matrix count means what it says.
- **Test:** Positive — a happy-path leg exiting 3 on an empty store is recorded `skip` with a
  reason and is excluded from `tests_passed`. Negative — an `error_path` leg exiting 3 stays
  `pass`, and a happy-path leg exiting 0 stays `pass`.
- **Evidence:** `library/other/pbs/.manuscripts/<run>/proofs/publish-live-gate.json` before the
  CLI fix; reproduced independently in the amazon-jobs, cdc-pakistan and nccpl gate artifacts
  listed above.
- **Related prior retros:** None found for this specific finding.

### 2. Scorecard gates its verdict on a dimension it excludes from its own denominator (Scorer bug)
- **What happened:** `live_api_verification` is documented as omitted from the denominator,
  alongside `auth_protocol` and `mcp_surface_strategy`, yet it is the only one of the three that
  lands in `unverified_dimensions` and qualifies the grade. PBS scored 84/100 grade
  "A (1 of 25 dimensions unverified: live_api_verification)" while every live path was
  hand-verified working: `index` returns `source:live`, `file` fetched 55,559 real bytes,
  `doctor` reported the API reachable.
- **Scorer correct?** No. `auth_protocol` is equally not-applicable on a no-auth CLI and does
  not qualify the grade; the asymmetry is the bug. Either an omitted dimension qualifies the
  verdict or it does not.
- **Root cause:** Verify/dogfood/scorecard — the omitted-from-denominator set and the
  unverified-dimensions set are not the same set.
- **Cross-API check:** Yes. Present in `.printing-press.json` for five CLIs — pbs (84),
  mufap (85), cdc-pakistan (80), nccpl (84), foodpanda (85) — each carrying
  `unverified_dimensions: ["live_api_verification"]` and a qualified grade string. Clean on
  psx (98), zameen (86), peekaboo (89). It fires across auth types (none, cookie, composed),
  so it is not auth-specific.
- **Frequency:** most APIs — 5 of 8 library CLIs carrying a scorecard block.
- **Fallback if the Printing Press doesn't fix it:** Moderate but corrosive. The operator learns
  to read a qualified A as "fine", which is exactly the habit that lets a real HOLD pass
  unexamined.
- **Worth a Printing Press fix?** Yes — small, contained, and it removes a permanent asterisk
  from the majority of printed CLIs.
- **Inherent or fixable:** Fixable.
- **Durable fix:** Derive `unverified_dimensions` by subtracting the omitted set, so a dimension
  cannot be both excluded from the denominator and cited in the grade. If live verification
  genuinely should gate, move it out of the omitted set and score it — but pick one.
- **Test:** Positive — a no-auth CLI with all live paths working scores an unqualified grade.
  Negative — a dimension that is genuinely in the denominator and unverified still qualifies it.
- **Evidence:** `scorecard.unverified_dimensions` and `scorecard.steinberger.grade` across the
  five CLIs above.
- **Related prior retros:** None found for this specific finding.

## Work Units

### WU-1: Record a non-zero-exit happy path as `skip`, not `pass` (from F1)
- **Stable ID:** WU-1
- **Priority:** P1
- **Type:** bug
- **Component:** scorer
- **Goal:** The live-dogfood matrix should never count a command that exited non-zero as a pass on a happy path, so the acceptance marker is usable as evidence.
- **Target:** Live dogfood happy-path/json-fidelity evaluator and the `--write-acceptance` writer.
- **Acceptance criteria:**
  - positive test: a happy-path leg exiting 3 against an empty local store is recorded `skip` with a reason naming the exit code, and is excluded from `tests_passed`
  - negative test: an `error_path` leg exiting 3 remains `pass`; a happy-path leg exiting 0 remains `pass`
- **Scope boundary:** Does not change which commands are exercised, does not change `error_path` semantics, and does not attempt to pre-populate local state for clean-room runs.
- **Dependencies:** None
- **Complexity:** small

### WU-2: Stop citing omitted dimensions in the scorecard verdict (from F2)
- **Stable ID:** WU-2
- **Priority:** P2
- **Type:** bug
- **Component:** scorer
- **Goal:** A dimension excluded from the denominator must not qualify the grade.
- **Target:** Scorecard dimension accounting — the omitted-from-denominator set and `unverified_dimensions`.

## Anti-patterns
- **A green matrix used as evidence without reading the exit codes inside it.** The gate said
  92/92 PASS three times running while six happy-path legs had exited non-zero. Verifying
  against the artifact's own summary rather than its contents is the same class of error as
  grepping a log for "success".
- **Fixing one path of a defect class and declaring the class closed.** The report-parse-failure
  path was correctly fixed to mark a release incomplete, with a comment explaining exactly why —
  while the adjacent PDF-only path, affecting 99 of 148 releases, kept the original bug.
- **Recording a placeholder observation to satisfy a data-model constraint.** The first attempt
  at naming the missing-report hole wrote `upstream_404` for CPI months whose report file never
  existed. A missing observation must be recorded as missing, not as a different observation
  that happens to be terminal.
- **Assuming a compound key is unique because its parts usually differ.** `as_of` looked like it
  encoded the series; it does not, and three dates in the live index carry both a weekly and a
  monthly release.
