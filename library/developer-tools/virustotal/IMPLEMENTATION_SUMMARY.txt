================================================================================
KEY DESIGN DECISIONS
================================================================================

1. Cache-first: Check SQLite before API to save quota
2. BFS for pivots: Avoids cycles, supports depth limits
3. Worker pools: Parallel enrichment with configurable concurrency
4. Separate LLM format: Preserves backward compatibility
5. Relationship tracking: Stores graph edges for offline re-querying
6. FTS5 search: Full-text search across all cached IOCs
7. Pure Go SQLite: No CGO, cross-platform builds

================================================================================
ERROR HANDLING
================================================================================

- Missing API key: configErr
- API errors: classifyAPIError
- Rate limiting: exponential backoff (in client)
- Invalid IOCs: regex validation with fallback
- SQLite errors: wrapped with context
- Network failures: retry logic

================================================================================
PERFORMANCE
================================================================================

- SQLite reads: Sub-millisecond
- SQLite writes: ~1ms per IOC
- Batch enrichment: Parallel workers, rate-limited
- Pivot traversal: O(V+E) BFS
- Memory: Minimal, streams results, mmap for SQLite
