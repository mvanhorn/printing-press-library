## Customer model

**Persona 1: Mara, solo operator with a small Mac fleet (about 8 devices)**

**Today (without this CLI):** She keeps the Tailscale admin console open in a browser tab and runs `tailscale status --json` on whichever Mac she's sitting at. Admin jobs go through a hand-written Python script, and expiry checks go through another script in the style of `check-all-macs.py`. Local status only shows peers visible from the current node, so "which of my machines lose their key this month" depends on running that script from the right machine. Changing a route or the policy file means a browser session.

**Weekly ritual:** Check key expiry across the fleet. When she sets up or retires a box, approve or remove its exit node or subnet route. Add a Taildrive `drive:share` / `drive:access` nodeAttrs entry when she wants a new machine to share files. Share a machine with a contractor and later take the share back.

**Frustration:** `POST /device/{id}/routes` replaces the whole enabled set. If a script approves an exit node without first reading `enabledRoutes`, it silently drops her existing subnet routes. Editing the policy outside the console risks losing HuJSON comments and overwriting a concurrent edit.

**Persona 2: Devin, IT admin for a company tailnet (tens to low hundreds of devices, tagged servers, subnet routers, auth keys)**

**Today (without this CLI):** He uses the admin console Machines page, filtered by hand, and tscli or the YawLabs MCP for raw endpoint calls. He can't easily answer three questions: which machine shares are open across all devices (the console and the tools show invites per device), which advertised routes are still waiting for approval tailnet-wide, and which auth keys or API tokens expire soon.

**Weekly ritual:** A weekly access review. He looks at new devices, pending routes and exit nodes, expiring device keys and auth keys, outstanding share invites, contractor `grants` in the policy file, and the configuration audit log.

**Frustration:** Every policy change is a whole-document write. Two admins editing at once collide on the ETag, and there is no built-in backup or diff before the write. Share invites, including unaccepted ones whose `inviteUrl` anyone can redeem, are only visible device by device.

**Persona 3: Mara's agent, a Claude Code session doing tailnet admin for her**

**Today (without this CLI):** User Vision records that live-testing needed a browser session and a hand-written Python script. Endpoint-mirror MCP tools give the agent raw `set_device_routes` and `update_acl`. So "make this Mac an exit node" becomes GET routes, compute the set, POST, and one wrong step drops routes. To map "this machine" to an API ID, the agent has to already know that the local status `ID` equals the API `nodeId`.

**Weekly ritual:** Several requests a week: "approve the exit node on the new box", "give my laptop Taildrive access to the NAS", "can my phone reach the NAS on 445", "who has the NAS shared", "what changed on this machine".

**Frustration:** It has no structured dry-run plan to show the human before a whole-object write. It also has no single call that returns the current state of one device (routes, expiry, shares, recent changes) before acting.
