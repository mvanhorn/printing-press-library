# v0 API CLI Brief

## API Identity
- Domain: v0 API v2 — Vercel's app-generation agent API (v0.dev / v0.app). Build full-stack apps from prompts, iterate via messages, preview live, deploy to Vercel.
- Base URL: `https://api.v0.dev/v2` (verified live)
- Users: Developers building app-generation products (custom chat UIs), agents/MCP clients, and power users automating v0 workflows.
- Data profile: Chats (id, title, privacy, metadata, vercelProjectId), Messages (role, parts[], finishReason, usage, attachments), Files (path, content, encoding), MCP Servers, Webhooks, Settings. Token usage + creditsCost on every generation — the API is credit-metered.
- Auth: `Authorization: Bearer $V0_API_KEY`. API keys created at v0 settings → keys. Canonical env var `V0_API_KEY`.
- Spec source: No public OpenAPI. Docs site exposes full reference at `https://v0.app/docs/api/v2.md` + per-endpoint `*.md` pages. All 41 v2 reference pages captured and parsed (93 API signature blocks) into a structured contract.

## Reachability Risk
- None. Live-tested with the user's API key: POST /v2/chats (create), GET /v2/chats, GET /v2/chats/{id}, GET messages, GET files, GET preview, PATCH chat, DELETE chat all return 200 with documented shapes. Error shape verified: `{"message":"Unauthorized"}` (401), `{"message":"Chat not found"}` (404).
- v1-era chats return `{"message":"API v2 does not support this chat."}` — v2 only serves chats created through v2 endpoints.
- Rate limits: not documented on v2; treat 429 as throttle-able, surface typed rate-limit errors.

## Top Workflows
1. **Create an app from a prompt** — `create chat` with message, systemPrompt, modelConfiguration (v0-mini/pro/max/max-fast), privacy, title, metadata; blocks until complete; returns chat + usage.
2. **Iterate on an existing chat** — send follow-up message (sync/async/streaming), poll messageId, read message parts (text/thinking/file-edit/search/bash/tool-call/agent-action), stop in-flight generation.
3. **Get generated code & preview** — fetch chat files (get/update/download as archive), get preview URL + short-lived token (x-v0-preview-token header).
4. **Manage infrastructure** — list/get/create/update/delete MCP servers (max 10/user) and webhooks (events: chat.*, message.*); trusted preview hosts settings.
5. **Track spend** — every response carries usage.tokens + usage.creditsCost (input/output/cacheRead/cacheWrite/total); power users watch credit burn across chats.

## Table Stakes (absorbed — match/beat)
- `v0-cli` (community npm, v1 API): chat create/list/get/message/update/delete/favorite, project mgmt, hooks, deploy, config setup with `--api-key`/`V0_API_KEY`/saved config precedence, `--output json|yaml|table`, interactive prompts (inquirer).
- Official `v0` npm SDK (v2, v3.0.2): `v0.chats.create/list/get/update/delete/duplicate/createStream/sendMessage/resume`, MCP servers, webhooks, files, deploy, vercel-project; typed error envelope `result.error`.
- Official v0 MCP server + `@v0-sdk/ai-tools`: agent-native tool surface for v0.
- Official `create-v0-sdk-app`: app template + `.agents/skills/v0/SKILL.md`.
- No existing CLI targets the v2 API with offline search, local store, or streaming capture — whitespace.

## Data Layer
- Primary entities: `chats`, `messages` (child of chat), `files` (child of chat, keyed by path), `mcp_servers`, `hooks`.
- Sync cursor: cursor pagination on `GET /chats` (limit 1-100, default 20) and `GET /chats/{id}/messages` (limit 1-100, default 20); cursor=null ends pages.
- FTS/search: full-text over chat titles + message content; search across both from one local store.
- Local store also keeps usage/creditsCost per message → spend analytics without re-polling.

## Product Thesis
- Name: **v0 CLI** (`v0-pp-cli`)
- Why it should exist: The official SDK and community CLI are interactive, synchronous, no-local-state wrappers. A v2-native CLI with streaming capture, offline chat/message search, credit-spend tracking, and structured agent output (JSON/csv/select) is the missing power-user surface — scriptable, composable, and agent-native where everything else is browser- or React-shaped.
- Category: `ai` (public-library category for AI API CLIs).

## Build Priorities
1. Chats CRUD + list/search with cursor pagination; create (sync/async/streaming) with model/privacy/skills/attachments flags.
2. Messages: send (sync/async/streaming), list/get, stop, resolve-task; parts-aware output (text/thinking/file-edit summaries).
3. Files: get/update/download; preview URL + token fetch.
4. MCP servers + webhooks CRUD; settings preview-hosts.
5. Sync + SQLite store; offline `search`; `spend` analytics over cached usage; deploy/vercel-project.
6. Transcendence: `chats create --stream` SSE capture, `messages tail --follow`, `spend` by chat/model/day, `search` offline, `doctor` auth check, MCP-server auth shape helpers.
