Observed 2026-09-27. Research only: no repository clones, package installs, credentials, browser fingerprint impersonation, proxy, or block bypass. Exact captures and status metadata are in `discovery/public-source/`; `capture-manifest.json` records URLs, response statuses, sizes, and SHA-256. ## Current public HTTP observations

Plain unauthenticated curl returned **200** for [English Tokyo ranking](https://tabelog.com/en/tokyo/rstLst/?SrtT=rt), [English restaurant detail](https://tabelog.com/en/tokyo/A1301/A130103/13294162/), [area autocomplete](https://tabelog.com/internal_api/suggest_form_words?sa=%E6%9D%B1%E4%BA%AC), and [keyword autocomplete](https://tabelog.com/internal_api/suggest_form_words?sk=%E3%83%90%E3%83%BC). Initial sandbox DNS failure was local network restriction, resolved by approved network escalation; it was not an upstream rejection. These successful routes do not establish universal IP or future reachability.

English list contract observed directly:

- `.list-rst[data-rst-id][data-detail-url]` identifies a card. Name/link: `.list-rst__rst-name-target`; rating: `.list-rst__rating-val` / `.c-rating__val`; count: `.list-rst__rvw-count-num`; station/meters/genres: `.list-rst__area-genre` (example `Onarimon Sta. 416m / Japanese Cuisine`). Preserve missing scores/budgets as unknown, never zero.
- Dinner/lunch values follow `.c-rating-v3__time--dinner` / `--lunch` with `.c-rating-v3__val`. Source values use `JPY`, unlike Gurume's yen-symbol price regex. `.list-rst__holiday-text` gives closed-day text; `.list-rst__search-word-item` exposes facilities; award badge text is present.
- `.c-page-count__num` contains `1`, `20`, `139392`. Next link is `a[rel=next].c-pagination__arrow--next`, observed `/en/tokyo/rstLst/2/?SrtT=rt`. Follow source pagination rather than inferring total pages from the visible page-number window.
- Sidebar GET form action is the current listing URL. Names: `utf8`, `lid`, `SrtT`, `svd`, `vac_net`, `svps`, `svt`; observed `SrtT=rt`, `vac_net=0`, date `20260927`, party options `1`–`99`, time options `1000`–`2400` in half-hour increments. **No static budget fields or budget-filter anchors** were found in this capture. English budget filters need fresh form evidence; do not adopt Gurume's legacy `LstCos` ranges without validation.
- Public first-party assets: `https://tblg.k-img.com/javascripts/assets/pepper/restaurant-pc/rst/inbound_restaurant_list.js` and `.../rst/inbound/inbound_restaurant_list/index.js` (cache-busted full URLs in captured HTML). The latter returned 200 / 2002 bytes and contained no search/autocomplete/budget route identifiers.

English detail contract observed directly: JSON-LD `@type=Restaurant`, `@id`, `name`, `image`, `address`, `geo.latitude/longitude`, `priceRange`, `servesCuisine`, `telephone`, `aggregateRating.ratingValue`, **`aggregateRating.ratingCount`** (not `reviewCount`). Sample score/count `3.47` / `529`. `streetAddress` is empty in JSON-LD but the HTML `Address` row contains the complete Japanese address. `Average price` and `Average price (Based on reviews)` are distinct; header lunch/dinner budget values identify meal by icon class. Table keys include `Business hours`, `Payment methods`, `Service charge & fee`, `Non-smoking/smoking`, `Private rooms`, `Drink`, `Service`, `Website`, and `Phone number`. Sushi breadcrumbs use native English genre **`RC010201`**, and station path **`R4539`**; old wrapper `RC0201` is not the English contract.

Autocomplete returns JSON arrays with `name`, `datatype`, `id_in_datatype`, `lat`, `lng`, plus `multiple_suggest_flg`, `related_info`, `id`, `duplicated`. Observed area types include `Prefecture`, `RailroadStation`, `AddressMaster`; keyword types include `DetailCondition`, `Genre0`, `Genre2`, `Genre3`. Preserve datatype rather than pretending every suggestion is a restaurant. English autocomplete was not established here.

## Main comparator: narumiruna/gurume

[Repository](https://github.com/narumiruna/gurume), tree SHA `fe4357d52ae30bd33a8c10d336ff0cbad0ef5792`, [MIT license](https://github.com/narumiruna/gurume/blob/main/LICENSE). Current [pyproject](https://github.com/narumiruna/gurume/blob/main/pyproject.toml) is `0.0.12`, Python >=3.12; runtime depends on BeautifulSoup, curl-cffi, MCP, Pydantic, Textual, Typer. [PyPI metadata](https://pypi.org/pypi/gurume/json) also says 0.0.12 but last wheel upload is **2026-05-30**, predating the August HTTP fix; published dependencies also differ. Do not assume current main behavior ships in PyPI.

Table stakes: area/cuisine/keyword discovery; source sorting; separate budgets, score and review count; machine-readable errors/pagination; autocomplete; base details; agent skill. Gurume CLI omits page selection, reservation flags, detail and suggestions that its API/MCP exposes. It has 29 mapped cuisines including izakaya but **no bar category**. Main's [catalog expansion PR #85](https://github.com/narumiruna/gurume/pull/85) reports **1,111 verified leaf subarea paths**, and the current tree contains `src/gurume/data/area_catalog.json` (270,696 bytes). Older TUI documentation that only lists three city paths understates main's catalog; the exact published-wheel coverage was not inspected. Natural-language parsing now belongs to the [agent skill](https://github.com/narumiruna/gurume/blob/main/skills/gurume-cli/SKILL.md), which warns about area+keyword mismatch.

Exact Japanese-wrapper contracts from [restaurant.py](https://github.com/narumiruna/gurume/blob/main/src/gurume/restaurant.py): `/rst/rstsearch` GET query `sa`, `sk`, `sw`, `SrtT`, `PG`. `SrtT`: `trend` / `rt` / `rvcn` / `nod`. Cuisine-only uses `/{area_slug}/rstLst/{cuisine_slug}/`; source says current pages ignore legacy `LstG`. Other coded query fields: `svd`, `svt`, `svps`, `LstCos`, `ChkOnlineBooking`, `ChkSeatOnly`, `ChkNewOpen`, `ChkRoom`, `ChkParking`, `LstSmoking`, `ChkCard`. These fields are **source-code observations, not newly replayed filter guarantees**.

[suggest.py](https://github.com/narumiruna/gurume/blob/main/src/gurume/suggest.py) uses `/internal_api/suggest_form_words?sa=...` or `?sk=...`; `{suggest_empty:true}` means upstream unavailable, not no matches. [detail.py](https://github.com/narumiruna/gurume/blob/main/src/gurume/detail.py) fetches base, then optional `dtlrvwlst/?PG=N`, `dtlmenu/`, `party/`; only optional menu/course 404 is tolerated. [retry.py](https://github.com/narumiruna/gurume/blob/main/src/gurume/retry.py) caps attempts at 3 and explicitly classifies 429; no published numeric source rate limit was found.

Failure evidence: [#88](https://github.com/narumiruna/gurume/issues/88) reports 403; [#89](https://github.com/narumiruna/gurume/pull/89) changed curl-cffi Chrome impersonation to Safari. The issue commenter also reports non-impersonated requests returning 200; this is their observation, not our implementation dependency. [#80](https://github.com/narumiruna/gurume/pull/80) live Osaka+お好み焼き returned mixed Hiroshima/Tokyo results, only 4/20 Osaka URLs. Prefer proven native area paths and expose filter mismatches. Recent refactor PRs explicitly skipped live checks.

## Bounded landscape and gaps

Searches covered CLI, MCP, skills/plugins, npm and PyPI. [npm exact search](https://registry.npmjs.org/-/v1/search?text=tabelog&size=10) returned total3: `hubot-tabelog`0.0.4 (chat restaurant picker), `@asolens/mcp`0.4.0 (unrelated App Store), `clawy-mcp-server`0.2.0 (paid USDC API gateway). These are candidates, not inspected implementations or adopted dependencies. [Official Tabelog developer post](https://tech-blog.tabelog.com/entry/software-design-202312-chatgpt) confirms a historical ChatGPT plugin; it supplies no current callable API contract. No absence claim beyond these bounded searches.

Recommended gaps for root approval: English native area/genre discovery including bars; source rating context and counts; honest filtering confidence; compact five-candidate output without detail N+1; a single Go binary; explicit detail requests; offline saved lists with source URL, fetched time and stale status; side-by-side factual comparison. Defer review-text harvesting, TUI/MCP server runtime, arbitrary score cutoffs, booking mutations and legacy API keys. Meaningful E2E should establish exact area/genre restriction, source-order preservation, separate meal budgets, missing-value behavior, 403/429/challenge distinction, partial pages, and offline list persistence.
