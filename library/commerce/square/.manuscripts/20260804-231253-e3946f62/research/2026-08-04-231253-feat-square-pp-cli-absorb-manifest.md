### Scope and risk notes

- No stubs are approved or planned.
- All six transcendence commands require hand-written Go after generation; none are generator-emitted endpoint aliases.
- Commands that query local data must report unsynced/stale inputs, drain SQLite rows before follow-up joins, reject `--data-source live`, and declare `// pp:data-source local`.
- `request check` is pure offline computation and declares `// pp:data-source computed`; it validates but never fabricates an API response.
- Money-moving and destructive operations remain behind dry-run, confirmation, read-only, and explicit sandbox/production protections.
- The run has no Square token, so authenticated live smoke testing is currently out of scope; mocks and schema-derived tests remain required.

### Rejected novel candidates

- Payout explainer: absorbed by the broader close reconciliation workflow.
- Catalog publish preflight: merchant-policy rules were not sufficiently grounded.
- Location anomaly report: thresholds would be speculative and hard to verify.
- Webhook replay simulator: unsafe arbitrary outbound mutation and secret-handling risk.
- Retry/idempotency log audit: no stable log ingestion contract.
- Loyalty retention cohorts: weaker weekly evidence than the surviving operational workflows.
