## Findings

### 1. `analytics` is annotated read-only but opens the store read-write and migrates it; unknown `--type` reports 0 (Bug)
- **What happened:**
  - `analytics` carries `mcp:read-only: true`, but opens the store with `store.OpenWithContext`. Per the store template that path does MkdirAll and migrate, and the store open sets WAL and mode 0600.
  - Run on a 0400 copy of a populated store, it changed the file bytes, switched the journal from `delete` to `wal`, and changed the mode to 0600. A read command (`market shops`) on the same copy left it byte-identical.
  - Separately, `analytics --type <not-a-resource-type>` returns `{"count": 0}` with exit 0. For example, `--type market_results` returned 0 while that table had 3,632 rows.
- **Scorer correct?** N/A (found by AQL CDR probes and manual repro).
- **Root cause:** `internal/generator/templates/analytics.go.tmpl:46` calls `store.OpenWithContext(cmd.Context(), dbPath)`. `store.go.tmpl:103-110` has a read-only `OpenReadOnly`/`OpenReadOnlyContext` that "Skips MkdirAll and migrate", which the MCP `sql` tool already uses. `analytics.go.tmpl:93` calls `db.Count(resourceType)` without checking that the type exists.
- **Cross-API check:** every printed CLI with a local store gets this template. 13 library CLIs have `analytics.go` with `store.OpenWithContext(` and `mcp:read-only`: dice-fm-events, dice-fm, etsy, eventbrite, exchangerate-api, getmentalhelp, ngccoin, numista, resident-advisor, seats-aero, spotify, ticketmaster, youtube.
- **Frequency:** every store-backed API
- **Fallback if the Printing Press doesn't fix it:** an agent sees the read-only hint and calls `analytics` freely. A newer binary then migrates an older store one-way, which breaks an older installed CLI on that store, and it rewrites read-only fixture or golden copies. A typo'd `--type` gives a confident 0. Neither is caught in practice.
- **Worth a Printing Press fix?** Yes. The annotation is a contract that MCP hosts and agents rely on, the template already has the read-only opener, and the fix is local.
- **Inherent or fixable:** fixable.
- **Durable fix:**
  - Open with `store.OpenReadOnlyContext` in `analytics.go.tmpl`, handling a missing store as "not synced yet", the way other read paths do.
  - Validate `--type` against the store's known resource types, and return a usage error listing them when it's unknown.
- **Test:**
  - Positive: run `analytics` on a chmod-0400 store copy; bytes, mode and journal mode are unchanged, and `--type <unknown>` exits 2 with a list of valid types.
  - Negative: `analytics --type <known>` counts match `SELECT COUNT(*)`.
- **Evidence:** reproduced 2026-11-18 on etsy-pp-cli (press 4.35.6) against a copy of a populated store; source lines verified on origin/main 404c3a3.
- **Related prior retros:**
  - #5228 (closed) — `extends`: `--dry-run` ran learn init, creating or migrating the local store. Same class: a non-mutating path that mutates the store.
  - #2488 (open) — `related-area`: dogfood lacks a stateful sync→analytics→search pass.

## Work Units

### WU-1: `analytics` honours its read-only contract and rejects unknown types (from F1)
- **Stable ID:** WU-1
- **Priority:** P2
- **Type:** bug
- **Component:** generator
- **Goal:** generated `analytics` never mutates or migrates the store, and never reports a confident 0 for an unknown resource type.
- **Target:** `internal/generator/templates/analytics.go.tmpl` (open path and `--type` validation); uses the existing `OpenReadOnlyContext` in `store.go.tmpl`.
- **Acceptance criteria:**
  - positive: on a chmod-0400 populated store copy, `analytics` (all modes) leaves bytes, mode and journal mode unchanged.
  - positive: `analytics --type <unknown>` exits 2 and names the valid types.
  - negative: `analytics --type <known>` count equals `SELECT COUNT(*) … WHERE resource_type=?`, and an absent store is still reported as "not synced".
- **Scope boundary:** does not change other commands' open paths, `--group-by` semantics, or the MCP annotation itself.
- **Dependencies:** None.
- **Complexity:** small

## Anti-patterns
- Annotating a command read-only while it shares the migrating open path with writers.

## What the Printing Press Got Right
- `store.go.tmpl` already has a correct read-only opener (`mode=ro` via the `file:` URI, no migrate), and the MCP `sql` tool uses it.
- The `analytics` annotation is honest about intent. Only the open path is wrong.
