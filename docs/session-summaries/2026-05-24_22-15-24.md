## Decisions

- Use `json_extract(data, '$.thread_id')` from EmailSummary API response for thread detection (not `parent_id` column which is the FK to parent mailbox)
- Guard `parent_id` injection in sync with `if _, ok := obj["parent_id"]; !ok` (same pattern as `parentFKKey`)
- Anchor LIKE patterns at start (`'approve%'` not `'%approve%'`) rather than using NOT LIKE exclusions
- Remove `$.resource_id` from mailbox association checks (stores target object ID, not mailbox ID)
- Document the reactive review loop as a workflow issue learning

## Stumbling Blocks

- **Reactive Greptile whack-a-mole**: 9 commits / 17 reviews to reach 4/5. Each fix exposed a new finding in the same or adjacent code. Root cause: no upfront self-review of novel command code before pushing.
- **Column semantic mismatch**: `parent_id` in `mailboxes_emails` typed table is the FK to parent mailbox, not a thread-parent reference. `syncDependentResource` unconditionally overwrote it with the mailbox UUID, making all thread/reply metrics meaningless.
- **`$.resource_id` misunderstanding**: Assumed `resource_id` in audit-log entries stored mailbox IDs. It stores oversight-item/upgrade-object IDs. Three queries had dead OR branches.
- **User frustration**: User explicitly called out the iterative one-fix-at-a-time approach twice.

## Learnings

- When hand-patching generated CLI code, always read: (a) the sync code to understand data ingestion, (b) the API spec for actual field names, (c) the typed table schema for column semantics. These three reads would have prevented 5 of 7 bugs.
- Greptile is a gate, not a code reviewer. Using it as your primary review loop scales linearly in tokens and wall time.
- Batch all fixes in one commit after thorough self-review. The user's preference for proactive completeness over iterative correctness was stated multiple times.

## Constraint-Removal Observations

1. **[compounding_asset]** The `docs/solutions/workflow-issues/` learning is a genuine compounding asset — it captures the anti-pattern so future sessions can avoid it.
2. **[feedback_loop]** The Greptile review loop IS a feedback loop, but it was used as the primary review instead of a validation gate. The right feedback loop is: self-review then push then Greptile confirms.
3. **[constraint_removal]** If Greptile didn't exist, you'd still need to self-review. The constraint isn't Greptile — it's the agent's failure to do upfront code review before pushing.
